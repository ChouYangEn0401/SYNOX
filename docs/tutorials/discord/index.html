SYNOX 接 Discord：從建 bot 到第一句回覆

一步一步把 Discord 的 bot 建好、接進 SYNOX、配對擁有者、測試、排錯。先挑你的情境，再往下做。看不懂的名詞，往下有「30 秒名詞」。

0

先挑你的情境

Discord 允許一支 bot 同時被私訊、放進伺服器、在不同頻道行為不同；SYNOX 今天做到的程度每種不一樣。

①

只有我自己用（私訊）

像 Telegram 一樣：私訊 bot 用全部功能、AI、按鈕、提醒。沒有別人。

風險低

建 1 個 Application → 做 1、2、3、4、5a、7、8、9

②

我和幾個朋友的私人伺服器

每個人私訊 bot 用自己的資料；想要的話再放一支「查詢用」的 bot 在一個頻道給大家用。

風險中

私訊型 1 個；頻道型選用再 1 個 → 全部步驟

③

公開頻道，誰都能叫

只放「頻道型」bot，唯讀、有節流、AI 額度小。私訊型 bot 是另一支，不要邀進公開伺服器。

風險高

頻道型 1 個 → 1–7、9、10 ＋ 安全

④

每個頻道不同功能

今天的做法是「一個頻道一支頻道型 bot」；真正的每頻道設定還沒做（有提案）。

風險中

每個功能組合 1 個 Application → 10

情境SYNOX 設定要建幾個 Application要開的 intent邀請連結的權限數字
① 只有我一支私訊型（surface: "dm"，預設）1Message Content2048（Send Messages；私訊不看伺服器權限）
② 私人伺服器私訊型 ＋（選用）頻道型 max_effect: "read" 或 "write"1 或 2Message Content頻道型 68608（View Channels＋Send Messages＋Read Message History）
③ 公開頻道只有頻道型，max_effect: "read"，節流留預設或更嚴2（私訊型留給自己）Message Content68608；不要給 Administrator
④ 每頻道不同每個頻道一支頻道型 bot，各自 packs／max_effect每個功能組合 1 個Message Content68608，再用 Discord 的頻道權限覆寫收窄
為什麼「一支 bot 同時私訊又在頻道回」要兩個 Application？Discord 本身允許同一支 bot 兩邊都做；是 SYNOX 把「私訊型」和「頻道型」分成兩種 bot（各自的 intent、各自的規則、各自的風險），一支 bot 的 surface 只能二選一。多建一個 Application 不用錢，一分鐘的事。觀念說明在 docs/discord-concepts.md。

建一個 Application

在 Discord Developer Portal · 每種情境都要 · 約 1 分鐘

  1. 用瀏覽器打開 discord.com/developers/applications，用你平常的 Discord 帳號登入。
  2. 右上角 New Application → 取名（例如 SYNOX；頻道型另一支可以叫 SYNOX 查詢）→ 勾同意條款 → Create。
  3. 進到 General Information 頁。這裡的 Application ID 之後邀請連結會用到（不是秘密）。

2

Bot 頁：拿 token

Developer Portal → 左邊 Bot · 每種情境都要

  1. 左邊選 Bot。新建的 Application 已經自帶一個 bot user（新版 Portal 不用再按 Add Bot）。
  2. Token 那一格按 Reset Token（有開兩步驟驗證會先要你輸入驗證碼）。
  3. 整串複製。只會顯示這一次；關掉頁面就看不到了，要再拿就再 Reset（舊的會失效）。
  4. 貼去哪：第 7 步的 SYNOX。不要貼到任何聊天、不要截圖、不要寫進 config.json。

3

同一頁往下：Privileged Gateway Intents

Bot 頁下半部 · 每種情境都要 · 沒開會連不上（4014）

  1. Bot 頁往下捲到 Privileged Gateway Intents。
  2. 把 Message Content Intent 打開。Presence Intent、Server Members Intent 不用開。
  3. 最下面會浮出綠色的 Save Changes，一定要按。

1三個特權 intent 的區塊。2只開 Message Content。3沒按 Save 等於沒開。
為什麼要這個？Discord 規定：bot 在伺服器裡收到的訊息，沒開這個 intent 時 content 是空字串（例外：@到 bot 的那則、私訊給 bot 的、回覆 bot 的）。SYNOX 不管私訊型或頻道型，連線時都一律宣告要 Message Content，所以沒開的話 Discord 會直接把連線關掉，SYNOX 狀態顯示「Developer Portal 沒開 Message Content intent（4014）」。
要審核嗎？不用。官方現在的規則：能看到這支 app 的不重複使用者超過 1 萬才要申請審核（舊規則是 100 個伺服器）。自己用、朋友的伺服器、小型公開頻道都遠低於這個數字，在 Portal 自己開就好。
4

OAuth2 → URL Generator：做邀請連結

Developer Portal → OAuth2 · 每種情境都要（私訊型也要，因為要先進一個伺服器）

  1. 左邊 OAuth2，往下找 OAuth2 URL Generator。
  2. Scopes 只勾 bot（applications.commands 會自動跟著 bot，勾不勾都行；SYNOX 沒有 slash 指令，用不到）。
  3. 勾了 bot 下面會出現 Bot Permissions：
    私訊型（情境 ①）只勾 Send Messages；
    頻道型（情境 ②③④）勾 View Channels、Send Messages、Read Message History。不要勾 Administrator。
  4. 最下面 Generated URL 按 Copy。這條網址裡有 client_id（＝Application ID）、scope=bot、permissions=數字，都不是秘密。

5

把 bot 邀進伺服器；私訊型再去私訊它

在 Discord 本體（桌面版或網頁版） · 每種情境都要

5a. 邀進伺服器（每一支 bot 都要做一次）

  1. 把第 4 步的網址貼到瀏覽器打開（要用有那個伺服器管理權限的帳號登入）。
  2. 「新增至伺服器」的下拉選單選伺服器。沒有伺服器？先在 Discord 左邊按「＋」建一個（免費、可以只有你一個人）；情境 ① 就建一個私人的。
  3. 看一眼它要的權限（就是你剛才勾的三個）→ 授權 → 人機驗證。
  4. 回 Discord，右邊成員清單會多一個 bot（離線也正常，SYNOX 還沒啟動）。

7

把 token 貼進 SYNOX

在你的電腦上 · 三條路擇一；多個 bot 走第三條

路怎麼做適合
A. 安裝精靈雙擊 Setup.bat → bot 那一頁選 Discord → 貼 token → 檢查 token → 下一頁就是配對（第 8 步）第一次裝、情境 ①
B. 網頁設定頁SYNOX 網頁 → 設定 → 聊天通道 → Discord → 貼 token → 存。會先向 Discord 驗證這支 bot 叫什麼，然後顯示邀請連結；改完要重新啟動 SYNOX已經在用網頁的人、情境 ①②
C. 終端機在 SYNOX 資料夾：.venv\Scripts\python.exe -m synox discord token（多個 bot 加 --bot 名字），貼上 token 按 Enter（畫面不顯示是正常的）；再改 config.json多個 bot、頻道型（情境 ②③④）

token 只存在保管箱 data\secrets.json.enc（加密），config.json 裡只寫保管箱的名字（vault:…），不會有 token 本身。A、B 兩條路會自己寫 config.json；C 要你自己改。

config.json 範例：情境 ① 只有我（一支私訊型）

"channels": { "discord": { "enabled": true, "bot_token": "vault:discord_bot_token" } }

只用 Discord、沒有 Telegram 的話，owner_id、bot_token（Telegram 的）可以不寫；SYNOX 會用保留號碼當擁有者，配對（第 8 步）之前誰的私訊都不收。

config.json 範例：情境 ②④ 私訊型＋頻道型（bots 寫法）

"channels": { "discord": { "bots": {
  "synox": {
    "token": "vault:discord_bot_token:synox",
    "surface": "dm", "packs": "all", "ai": true
  },
  "lookup": {
    "token": "vault:discord_bot_token:lookup",
    "surface": "channel",
    "guilds": { "123456789012345678": {
        "channels": ["234567890123456789"],
        "role_map": { "345678901234567890": "member" } } },
    "trigger": "mention",
    "packs": ["dict"],
    "max_effect": "read",
    "rate_per_minute": 5
  }
} } }

每支 bot 各存一次 token：python -m synox discord token --bot synox、… --bot lookup。bot_token 和 bots 兩種寫法擇一，不能並存。

config.json 範例：情境 ③ 公開頻道（只有頻道型，保守設定）

"channels": { "discord": { "bots": {
  "public": {
    "token": "vault:discord_bot_token:public",
    "surface": "channel",
    "guilds": { "123456789012345678": { "channels": ["234567890123456789"] } },
    "trigger": "mention",
    "packs": ["dict"],
    "max_effect": "read",
    "rate_per_minute": 3,
    "room_rate_per_minute": 10,
    "ai": { "enabled": true, "pool_usd_month": 2, "rate_per_minute": 1,
            "persona": "你是這個頻道的小幫手，只回答查得到的事。" }
  }
} } }

沒列在 guilds 的伺服器與頻道一律不讀不回。max_effect 不能寫 danger（會被拒）。ai 要就一定要有 pool_usd_month（整支 bot 每月的額度，美元），不要就整段拿掉。

改完先檢查。.venv\Scripts\python.exe -m synox doctor --offline：Discord： 底下每支 bot 一行，要看到「✅ token 在保管箱」；哪一格寫錯會直接說。
8

配對：告訴 SYNOX 哪個 Discord 帳號是擁有者

情境 ①② 必做（有私訊型 bot 就要）；只有頻道型 bot 的情境 ③ 不用

沒配對之前，私訊型 bot 誰的私訊都不收（回一句「還沒配對」），免得第一個來私訊的陌生人被當成擁有者。三條路擇一：

路怎麼做備註
A. 精靈第 7 步 A 的下一頁：畫面出現六位數字 → 照畫面打開邀請連結（5a）→ 在伺服器成員清單私訊 bot，傳那六個數字 → 畫面變「✅ 認得你了」精靈自己開一條連線等你，不用先啟動 SYNOX
B. 網頁SYNOX 要先啟動（bot 上線）→ 網頁 設定 → 聊天通道 → Discord → 「配對我的 Discord 帳號」 → 六位數字 → 私訊 bot 傳它 → 網頁顯示配對好了。也可以點「手動」直接貼你的 Discord 使用者 ID（第 6 步）15 分鐘有效；傳錯 10 次就作廢要重產
C. 終端機先 Stop.bat 關掉 SYNOX → .venv\Scripts\python.exe -m synox discord pair（多個 bot 可加 --bot synox，要私訊型的）→ 六位數字 → 私訊 bot 傳它 → 命令列印「✅ 已把 Discord 帳號 … 接到擁有者」或在 config 的 channels.discord 寫 "owner_user_id": "<你的使用者 ID>"

1只傳那六個數字，不要加別的字。2這句出現就配好了，記在 data\identities.json；同一個 Discord 帳號對哪一支私訊型 bot 都是同一個人，配對一次就好。3之後啟動 SYNOX（Start.bat）再私訊 /help 就該有回覆。

9

啟動、測試

每種情境 · 照順序打勾

  1. 雙擊 Start.bat（或 .venv\Scripts\python.exe -m synox run）。小視窗出現「✅ SYNOX 開始收訊息了」；有 bot 沒開成會印「⚠️ Discord bot X 沒有開：原因」。
  2. Discord 成員清單裡的 bot 應該變成線上（綠點）。還是離線 → 看「疑難排解：bot 離線」。
  3. 私訊型：私訊 bot 打 /help，要有指令清單。再試一個會出按鈕的指令、一個 AI 問題（如果有設 AI）。
  4. 頻道型：到列出的頻道打 @SYNOX查詢 /help（要真的 @ 到 bot，不是打名字）。回覆會引用你那則訊息。到沒列的頻道 @ 它，應該不回。
  5. 私訊 SYNOX 打 /bot_status：每支 bot 的狀態、會出現哪些工具、「設定了但不會出現」的原因。
  6. 陌生人測試（有第二個 Discord 帳號才做）：個人版應該被擋；伺服器版變成訪客。
  7. 重開（Stop.bat → Start.bat）：配對還在、私訊照常。
頻道型 bot 今天只會回 /help、/start、/exit。因為頻道裡只會出現 pack.json 宣告了 "surfaces": ["dm","channel"]、而且 data 不是 user 的工具，目前出廠與工具庫裡沒有任何工具這樣宣告。所以頻道裡 /help 幾乎是空的是正常的，不是壞掉。開了頻道 AI 可以聊天但沒有工具。

完整的 D1–D18 測試清單在 docs/handoff/discord-handoff.md 第 9 節；上線前也可以先跑 scripts\smoke_real.py --only discord（只查 token、bot 身分、intent、配對，不上線）。

10

伺服器頻道、每個頻道不同功能

情境 ②③④ · 這一步是「能做到什麼」的誠實版

Discord 給你的兩層控制

第一層：頻道權限覆寫（Discord 擋）

伺服器設定 → 頻道 → 權限：把 bot 的身分組在某個頻道的 View Channel 關掉，那個頻道的訊息根本不會送到 bot；關 Send Messages 就收得到、回不了。這層最可靠，設定寫錯也擋得住。

第二層：bot 自己看 channel_id（SYNOX 擋）

每則訊息都帶 guild_id、channel_id。SYNOX 頻道型 bot 的 guilds 就是用這個做 allowlist：沒列的不讀不回。

SYNOX 今天做到的

你想要今天說明

頻道裡跟 AI 聊✅ai.pool_usd_month 一池；記憶是頻道共用的；回覆前遮罩 token
Discord 身分組 → 誰能用寫入工具✅role_map 最高到成員；寫入還要 max_effect: "write"＋工具 data: shared

Discord 原生 / 指令選單、收附件❌沒做

情境 ④ 今天的做法：一個頻道一支 bot

"bots": {
  "me":     { "surface": "dm", "packs": "all" },
  "lookup": { "surface": "channel", "packs": ["dict"], "max_effect": "read",
              "guilds": { "<伺服器 id>": { "channels": ["<#查詢 的 id>"] } } },
  "log":    { "surface": "channel", "packs": ["shared-list"], "max_effect": "write",
              "guilds": { "<伺服器 id>": { "channels": ["<#記錄 的 id>"],
                          "role_map": { "<身分組 id>": "member" } } } }
}
  • lookup、log 各是一個 Application、各一個 token、各自邀進伺服器；成員清單會是兩個名字（「SYNOX 查詢」「SYNOX 記錄」），大家反而清楚在 @ 誰。
  • 再用第一層（頻道權限覆寫）把 lookup 的身分組從 #記錄 拿掉，反之亦然，雙保險。
  • 缺點：Application 數量跟功能組合一起長；每支 bot 一條連線（十幾支以上要注意 Discord 對同一 IP 的連線頻率）。
提案（還沒做）：真正的每頻道設定。讓 guilds.<伺服器>.channels 的每一項除了 id 字串也能寫成物件 {"packs": [...], "max_effect": "read", "trigger": "/", "ai": false}，沒寫的沿用 bot 的；收訊時算出一個「這個頻道的派生 BotSpec」丟給現有的 policy.using_bot，權限判斷、/help、AI 工具清單、節流一行都不用改。細節在 docs/discord-concepts.md 第 7 節，要不要做由擁有者決定。

疑難排解

看到什麼意思怎麼辦
bot 一直離線（成員清單灰點）SYNOX 沒啟動、或這支 bot 沒開成看 Start.bat 小視窗：「⚠️ Discord bot X 沒有開：原因」。沒有這行但還是離線 → python -m synox doctor；再看下面 4014／4004
「Developer Portal 沒開 Message Content intent（4014）」／ Used disallowed intent(s)第 3 步沒開或沒按 Save；或 token 是另一個 Application 的（開錯支）Bot 頁 → Privileged Gateway Intents → Message Content → Save Changes → 重開 SYNOX。確認 token 跟你開 intent 的是同一個 Application
「bot token 不對（4004）」／ 401token 貼錯、少字、或按過 Reset Token回 Bot 頁再 Reset 一次，python -m synox discord token（--bot X）重存，重開
Missing Access（50001）bot 看不到那個頻道（沒有 View Channel，或頻道有私人覆寫）伺服器設定 → 頻道權限：給 bot 的身分組 View Channel；或把 bot 加進那個私人頻道的成員
Missing Permissions（50013）看得到但不能做這件事（通常是 Send Messages 或 Read Message History）同上補權限；或重做第 4、5 步用 permissions=68608 的連結再邀一次（不用先踢掉）
Cannot send messages to this user（50007）bot 跟那個人沒有共同伺服器，或對方關了「允許伺服器成員私訊」把 bot 邀進一個對方也在的伺服器；對方的隱私設定要允許來自伺服器成員的私訊
私訊沒回，bot 線上還沒配對（會回「還沒配對」）；或你不是擁有者（個人版擋陌生人）；或 intent 沒開（其實會連不上）第 8 步；用擁有者的帳號；/bot_status 看身分那行
頻道裡沒回，bot 線上頻道沒列在 guilds；沒真的 @ 到 bot；私人頻道沒給權限；講太快被節流；編輯過的訊息、只有附件的訊息一律不回照 docs/handoff/discord-handoff.md「頻道沒反應：照順序檢查」1–10
頻道回「頻道裡只收指令；想聊天請私訊」被 @ 但不是指令，頻道 AI 沒開正常；要聊就設 ai.pool_usd_month
「🔒 這個動作要到私訊做」頻道裡要確認卡或危險動作正常；去私訊做
429 Too Many Requests打 Discord 太快SYNOX 會等；頻繁出現就調低節流、別同時開太多 bot
token 外洩了貼錯、截圖、進了 git、別人看到立刻 Portal → Bot → Reset Token（舊的馬上失效）→ 重存 → 重開。保管箱那份用 discord token --clear 刪只是本機不再存，不會讓舊 token 失效
「加 --bot <名字> 指定存哪一個」config 用 bots 寫法但 discord token 沒指定加 --bot 名字
「同時寫了 bot_token 和 bots」兩種寫法混用擇一

還沒驗證的事（誠實清單）

  • 整條 Discord 通道還沒跟真的 Discord 連過：所有測試用程式內的假 Gateway、假 HTTP。第一次真連請照 docs/handoff/discord-handoff.md 做，有問題照它的格式回報。
  • User Install 能不能讓 SYNOX 收到私訊文字：官方說 User Install 的 app「只能用指令」（slash），SYNOX 沒有 slash 指令。docs/discord.md 把 User Install 列為選項之一，先當作未驗證；本教學走「邀進伺服器」。
  • 「沒有共同伺服器就收不到私訊」：官方只給錯誤碼 50007，「要共同伺服器」是社群共識＋SYNOX 精靈的假設。
  • Discord 選單的確切名稱（「複製伺服器 ID」、「進階」、「Installation」…）：官方支援中心文章本次抓取被擋，名稱來自社群轉述；以你手上的版本為準，找最接近的。
  • 特權 intent 審核門檻：官方文件現在寫「1 萬個不重複使用者」，網路上很多文章還是舊的「100 個伺服器」。兩者對個人使用都不會碰到。
  • 手機版開發者模式的位置：各版本不同（外觀／進階）。
