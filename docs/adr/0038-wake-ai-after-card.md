# ADR 0038：核准卡執行完叫醒 AI

- 日期：2026-11-17
- 狀態：**提案（契約定稿）**。實作在同時進行的分支 `feat/ai-structured-results`；那個 PR 自己的 ADR 寫實作細節，介面以這份為準。
- 基準：分支 `dev`，commit `86a930d`。文中的 `檔案:行號` 都是這個 commit 的。
- 來源：合一規劃（維護者的私有文件庫，2026-11-17）第 11.10 節；給 AI 的那一份結果的格式照同一份規劃的第 11.6 節（那個分支的 ADR 定）。
- 相關：[0037](0037-approval-cards-upgrade.md)（卡）、[0035](0035-workmode-core.md)（套用後的核對結果）、[0036](0036-triangle-review.md)（驗證者）、
  [0008](0008-completion-guard.md)（證據帳本）、[0025](0025-guard-core-and-stepup.md) §2（來源）。
- 程式：`src/synox/agent/approve.py`（`on_done` → `on_outcome`）、`agent/loop.py`（`wake()`、證據帳本的預先登記）、`agent/__init__.py`（接線）。
- 測試：`tests/test_agent_wake.py`。

## 背景

現在按了 ✅ 之後（**已查證** `src/synox/agent/approve.py:139`、`agent/loop.py:224`）：結果直接給人看，AI 的記憶裡只多一句
「使用者按了 ✅，已執行 …」。AI **不知道結果是什麼**，也不會接著做下一步。於是：

- 「刪掉之後再幫我整理一下」做了一半就停，使用者要再說一次；
- 下一輪 AI 說「已經刪好了」時，它其實沒看過結果；
- 批次方案套用之後的核對結果（[0035](0035-workmode-core.md)）沒有人交給 AI。

## 決定

| # | 題目 | 決定 |
|---|---|---|
| 1 | 什麼時候叫醒 | AI 引起的卡有了結果：執行了（成功或失敗）、被取消、過期、按的時候發現資料變了。**各叫醒一次** |
| 2 | 叫醒是什麼 | 把結果寫進那段對話的記憶，再開一輪。那一輪的 user 訊息是系統寫的 `[系統事件] …` |
| 3 | 給 AI 的結果 | 跟 AI 自己叫工具時拿到的是同一種（訊息＋精簡的 JSON），包在那一輪的分隔符裡 |
| 4 | 證據 | 卡片執行的那幾筆預先登記進叫醒那一輪的證據帳本，AI 才可以說「做好了」 |
| 5 | 防迴圈 | 一句人話之後最多**連續叫醒 3 次**（提案值）。超過＝不開輪，只記一筆、告訴人 |
| 6 | 不混輪 | 人話與叫醒事件永遠不是同一輪；同一段對話一次只跑一輪 |
| 7 | 權限 | 叫醒的那一輪照常走 `ai_decision`、第 4 關、核准卡。叫醒不帶任何額外的權限 |
| 8 | 不叫醒的 | 人自己打指令引起的卡（沒有 AI 在等）；AI 自己收回的卡；頻道 AI；額度用完時 |
| 9 | 開關 | `llm.wake_after_card`：`true`（預設）｜`false`（退回舊行為：只記一句） |

## 契約

### 1. 卡的結果：`Outcome`

`ApprovalDesk` 的回呼從 `on_done(chat_id, note, user_id, thread)` 換成 `on_outcome(outcome)`。
舊的 `on_done` 留一版（有設就照舊呼叫，字不變），之後拿掉。

```python
@dataclass(frozen=True)
class OutcomeItem:
    tool: str                 # AI 看到的工具名（<群組>__<指令>）
    shown: str                # 卡上那一行
    effect: str               # read｜write｜danger
    args: dict                # AI 當時給的參數
    ran: bool                 # 有沒有真的執行
    ok: bool                  # 執行成功（沒執行＝False）
    result: str               # 給 AI 的那一份結果（已經照上限截過；沒執行＝""）
    receipts: tuple = ()      # 排程回執（ADR 0029 §3.2）

@dataclass(frozen=True)
class Outcome:
    card_id: int
    kind: str                 # action｜work_apply｜tool_confirm｜habit
    source: str               # ai｜human｜tool
    status: str               # executed｜failed｜cancelled｜expired｜stale｜denied
    chat_id: int; user_id: int; thread: str | None
    items: tuple[OutcomeItem, ...]
    report: dict | None = None        # work_apply：workmode.report() 的結果
    via: str = ""                     # 在哪裡按的：telegram｜discord｜web（過期＝""）
```

| `status` | 意思 |
|---|---|
| `executed` | 全部執行成功 |
| `failed` | 至少一個執行了但失敗（併卡時：第 k 個失敗、後面沒做；`items[].ran`／`ok` 一筆一筆寫清楚） |
| `cancelled` | 人按了 ❌ |
| `expired` | 過期，沒有執行 |
| `stale` | 按 ✅ 時發現資料變了，沒有執行（批次方案） |
| `denied` | 按 ✅ 時以人的身分 authorize 不過，沒有執行 |

「還沒解鎖、請他解鎖再按」不是結果（卡還開著），不產生 `Outcome`。

`result` 怎麼來：卡片執行時用 `CaptureApi` 接（跟 AI 直接叫工具同一條路），輸出**同時**照常給人看。給 AI 的那一份照規劃第 11.6 節：
信封的 `message`＋精簡的 JSON（有 `ai` 欄位用它，沒有用 `data`），上限 `llm.tool_result_chars`，過 `mcp.redact`。

### 2. `AgentLoop.wake(outcome, api)`

```python
def wake(self, outcome: Outcome, api) -> bool        # True＝開了一輪；False＝只記了一筆
```

`api`＝回覆要走的管子：按鈕來的那個（`cb` 的通道；網頁就是那一段對話）。過期沒有人按＝那張卡當初送出去的通道（卡上記著 `chat_id`、`thread`）。

步驟（照順序）：

1. `outcome.source != "ai"`、`llm.wake_after_card` 是 `false`、或這個人現在不能用 AI（`ai_decision` 對 `agent.ai` 不過）＝只記一筆（下面第 5 點的字）、回 `False`。
2. 連續叫醒的次數（第 4 節）已經到上限＝只記一筆，並由系統送一則給人：「（AI 已經連續接手 3 次，先停在這裡。要它繼續就跟它說一聲。）」回 `False`。
3. 額度用完（`out_of_budget`）＝只記一筆、回 `False`（不另外送「額度用完」；那句話在他下一次說話時照舊會出現）。
4. 丟到 `app.tasks`（不卡收訊的執行緒），在那段對話的鎖裡（`self._locks[memory_key]`）跑一輪：
   - user 訊息＝`wake_text(outcome, nonce)`（下面第 3 節）。
   - 來源（ADR 0025 §2）：這一輪是 `ai`，`on_behalf`＝按的那個人的來源（`executed`／`cancelled`…）；過期＝`system`。
   - 證據帳本預先放進 `outcome.items` 裡 `ran=True` 的每一筆：`Evidence(tool, effect, ok, carded=False, args, result[:200], receipts)`。
   - 其餘跟平常的一輪完全一樣：同一份系統提示、同一份工具清單、`ai_decision`、第 4 關、核准卡、完成宣稱的閘門、步數上限。
5. 記憶：這一輪結束時照常 `remember(chat_id, <事件的一行摘要>, <AI 的回覆>)`。摘要是系統寫的固定格式（例如「（系統）確認卡 #12 已執行：cal__plan_apply」），
   不是整份結果——結果只在這一輪的訊息裡，不永久留在記憶（記憶只有 6 輪）。

### 3. 事件的字：`wake_text(outcome, nonce)`

固定的樣板（程式裡的常數）；工具的結果在分隔符**裡面**，其他每個字都是系統寫的：

```
[系統事件] 使用者核准了確認卡 #12，已執行：
1. cal__plan_apply（成功）
⟦…這一輪的分隔符…⟧
已套用 26 步。{"batch_id": "b_7f2", "steps": 26, "applied": 26}
⟦…⟧
[系統核對] 🔎 套用後核對：26/26 筆對上、範圍內沒有多的、規則檢查 0 條
接下來：向使用者回報結果。已經執行的動作不要再做一次。
```

| `status` | 第一行 | 最後一行 |
|---|---|---|
| `executed` | 「使用者核准了確認卡 #N，已執行：」 | 「向使用者回報結果。已經執行的動作不要再做一次。」 |
| `failed` | 「使用者核准了確認卡 #N，執行時有失敗：」＋每一筆寫（成功）／（失敗）／（沒有執行） | 「照實告訴使用者哪些做了、哪些沒做；不要自己重試危險的動作。」 |
| `cancelled` | 「使用者取消了確認卡 #N，**沒有執行**：」 | 「不要再提出同一個動作，除非使用者要求。」 |
| `expired` | 「確認卡 #N 過期了，**沒有執行**：」 | 「告訴使用者這張卡過期了；他還要的話再提一次。」 |
| `stale` | 「確認卡 #N 沒有執行：資料在使用者看卡之後變了。」 | 「重新查詢、重新規劃。」 |
| `denied` | 「確認卡 #N 沒有執行：使用者現在沒有這個權限。」 | 「告訴使用者沒有執行；不要換別的方法做同一件事。」 |

- `report` 有的話（批次方案）：多一段 `[系統核對]`＝`report["headline"]`＋`diff_lines`。核對沒過時最後一行改成「核對沒過：把差異告訴使用者，他可以按『↩ 整批退回』。不要自己修。」
- 每個動作的 `args` **不放**進這段字（AI 當初自己給的，記憶裡有；也避免把長參數再送一次）。
- 整段上限：每個 `result` 照 `llm.tool_result_chars`；動作超過 12 個不會發生（[0037](0037-approval-cards-upgrade.md) 的併卡上限）。

人看到的東西不變：執行的輸出、`report` 的結果訊息照舊由系統直接送；叫醒那一輪 AI 的回覆是**另外一則**，在它們後面。

### 4. 防迴圈

- 每段對話（記憶鍵）一個計數 `wake_chain`：開一輪叫醒＝加 1；**人說了新的一句＝歸零**。到 `WAKE_MAX = 3` 之後的叫醒不開輪。
- 驗證者沒過叫醒執行者修一次（[0036](0036-triangle-review.md)）也算一次。
- 叫醒的那一輪可以再提出危險動作（再出一張卡）；那張卡的結果又會叫醒——所以才要計數。
- 同一張卡只叫醒一次（`card_id` 記在一個小集合裡，重複的 `Outcome` 丟掉）。
- 計數只在記憶體；重開歸零（重開之後卡都沒了，不會有殘留的叫醒）。

### 5. 不混輪

- 一段對話一次只跑一輪：`run_turn` 與 `wake` 用同一把鎖。人話正在跑＝叫醒排在後面；叫醒正在跑＝人話排在後面。
- 等著的叫醒最多留 3 個；同一段對話有好幾個在等時**合成一輪**（事件的字一段接一段，每段各自的 `[系統事件]` 開頭）。
- 人的訊息**永遠不會**被接在 `[系統事件]` 後面變成同一則 user 訊息。
- 等著的叫醒如果等到人說了新的一句：照樣跑（在那一輪之後），但它不歸零那句人話之後的計數。

## 不做的事

- **不替 AI 重試**：執行失敗就是失敗，交給 AI 與人決定。
- **不在叫醒時放寬任何檢查**：不跳過核准卡、不跳過第 4 關、不帶解鎖。
- **不把整份結果永久留在記憶**。
- **人自己打指令引起的卡不叫醒**：沒有 AI 在等。照舊記一句進 AI 的記憶（下一輪 AI 知道那件事做了沒）。
- **頻道 AI 不叫醒**（它本來就不出卡）。常駐助理（心跳）不受影響、也不因為卡的結果被叫。
- **不跨通道**：在 Telegram 提出、在 Telegram 按，回覆就在 Telegram；不會跑到網頁的另一段對話。
- **重開之後不補叫**。

## 測試怎麼寫

`tests/test_agent_wake.py`（`BotHarness`、`FakeAdapter` 照劇本回話、假工具、假時鐘；`app.tasks` 用同步的假實作，不開執行緒也測得到順序）：

1. 按 ✅：`FakeAdapter` 多被叫一次；那一次的最後一則 user 訊息以 `[系統事件]` 開頭、有 `#編號`、工具結果在分隔符裡面、是合法的精簡 JSON 而且在上限內。
2. 人看到的：執行的輸出一則、AI 的回覆另一則，順序對；執行的輸出跟以前一個字不差。
3. 證據：叫醒那一輪 AI 說「已經刪好了」＝完成宣稱的閘門放行（帳本裡有卡片執行的那一筆）；卡被取消時說「已經刪好了」＝被擋。
4. 取消、過期、`stale`、`denied`：各叫醒一次，第一行與最後一行是表上的字，裡面有「沒有執行」。
5. `failed`（併卡，第 2 個失敗）：三個動作分別標（成功）／（失敗）／（沒有執行）。
6. 批次方案：有 `[系統核對]` 那一段；核對沒過時最後一行是「不要自己修」。
7. 防迴圈：劇本讓 AI 每次被叫醒都再提出一個危險動作、每次都按 ✅：第 4 次不開輪，人收到「先停在這裡」那一則；人說一句之後又可以。
8. 同一張卡的 `Outcome` 送兩次：只叫醒一次。
9. 不混輪：人話那一輪還沒跑完時按 ✅：叫醒在它之後才跑；兩輪的 user 訊息各自獨立（沒有一則同時含人話與 `[系統事件]`）。
10. 兩張卡幾乎同時有結果：合成一輪，兩段事件都在。
11. `source="human"` 的卡（人自己打危險指令）：不開輪，記憶裡有一句。
12. `llm.wake_after_card = false`：行為跟現在一模一樣（既有的卡片測試不改就過）。
13. 額度用完：不開輪。成員沒有 AI 權限：不開輪。
14. 叫醒那一輪的工具呼叫照常被 `ai_decision` 擋／放；叫醒那一輪再出的卡照常要人按。
15. 來源：叫醒那一輪裡工具看到的來源是 `ai`、`on_behalf` 是按的那個人；過期的是 `system`。宣告 `callers` 只收 `human` 的指令在叫醒那一輪照樣叫不到。
16. 網頁：在哪一段對話按的，回覆就在那一段；另一段對話的記憶沒有變。
17. `scripts/eval_assistant.py` 既有題目的分數不退。

## 跟規劃不一樣的地方

| 規劃 | 這份 | 為什麼 |
|---|---|---|
| 「把結果寫進那個聊天的記憶」 | 結果只在叫醒那一輪的訊息裡；記憶裡留一行摘要＋AI 的回覆 | 記憶只有 6 輪、而且每輪都重送；整份結果留在記憶會一直佔脈絡 |
| 取消、過期各叫醒一次 | 多 `stale`、`denied`、`failed` 三種 | 卡有這三種結局（[0037](0037-approval-cards-upgrade.md)），AI 要分得出來 |
| 一件事最多連續叫醒 3 次 | 「一件事」＝一句人話之後；驗證者的修正也算在裡面 | 要有一個程式判斷得了的界線 |
| 沒寫開關 | `llm.wake_after_card` | 這是行為上的大改動，出問題時要能一行關掉 |
| 沒寫人引起的卡 | 不叫醒 | 那時沒有 AI 在等結果 |
