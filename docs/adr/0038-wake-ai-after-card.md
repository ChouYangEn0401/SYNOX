# ADR 0038：核准卡執行完叫醒 AI

- 日期：2026-11-17
- 狀態：**第一段已經有程式**（同時進行的分支 `feat/ai-structured-results`：`src/synox/agent/wake.py`、`tests/test_ai_wake.py`）；
  **之後兩段是提案**（批次方案的卡、併卡、過期）。這份把第一段的介面記下來，並定後兩段要怎麼接上去。
- 基準：分支 `dev`，commit `86a930d`；第一段的介面讀的是 `feat/ai-structured-results` 在 `71f4272` 的樣子（**已查證**，只讀）。
- 來源：合一規劃（維護者的私有文件庫，2026-11-17）第 11.10 節；給 AI 的那一份結果照同一份規劃的第 11.6 節（`src/synox/agent/structured.py`）。
  **兩邊重疊的地方以規劃與那個分支的實作為準**；這份不重新定義它們。
- 相關：[0037](0037-approval-cards-upgrade.md)（卡）、[0035](0035-workmode-core.md)（套用後的核對結果）、[0036](0036-triangle-review.md)（驗證者）、
  [0008](0008-completion-guard.md)（證據帳本）、[0025](0025-guard-core-and-stepup.md) §2（來源）。

## 背景

以前按了 ✅ 之後（**已查證** `dev` 的 `src/synox/agent/approve.py:139`、`agent/loop.py:224`）：結果直接給人看，AI 的記憶裡只多一句
「使用者按了 ✅，已執行 …」。AI **不知道結果是什麼**，也不會接著做下一步。於是：

- 「刪掉之後再幫我整理一下」做了一半就停，使用者要再說一次；
- 下一輪 AI 說「已經刪好了」時，它其實沒看過結果；
- 批次方案套用之後的核對結果（[0035](0035-workmode-core.md)）沒有人交給 AI。

## 決定

| # | 題目 | 決定 | 哪一段 |
|---|---|---|---|
| 1 | 什麼時候叫醒 | **AI 發的卡**有了結果：執行了（成功或失敗）、被取消、按的時候已經不能執行。各叫醒一次 | 一（已有） |
| 2 | 叫醒是什麼 | 結果寫進那段對話的記憶，再開**自己的一輪**；那一輪的 user 訊息是系統寫的 `[系統事件] …` | 一 |
| 3 | 給 AI 的結果 | 跟 AI 自己叫工具時拿到的是同一種（訊息＋精簡的 JSON）。記憶裡放的是一個記號，每一輪組訊息時才換成「包在這一輪分隔符裡的結果」 | 一 |
| 4 | 證據 | 卡片執行的那一筆預先放進叫醒那一輪的證據帳本，AI 才可以說「做好了」 | 一 |
| 5 | 沒有要接著做的 | AI 只回一個固定的記號（`〔沒事〕`）：不送出、不進記憶 | 一 |
| 6 | 防迴圈 | 同一段對話最多**連續叫醒 3 次**；人說了一句話就重新算。超過的只寫記憶、不開輪 | 一 |
| 7 | 不混輪 | 人話與叫醒事件永遠不是同一輪；同一段對話一次只跑一輪（同一把鎖） | 一 |
| 8 | 權限 | 叫醒的那一輪照常走 `ai_decision`、第 4 關、核准卡、完成宣稱檢查。叫醒不帶任何額外的權限 | 一 |
| 9 | 不叫醒的 | 人自己打指令出的卡；頻道 AI；指令開了問答在等人（例如問驗證碼）；額度用完 | 一 |
| 10 | 批次方案的卡 | 多帶一段系統核對（`workmode.report()`）；按的時候發現資料變了也叫醒 | 二（跟工作模式一起） |
| 11 | 過期 | 卡過期也叫醒一次（「沒有執行」）。批次方案的卡先做，其他的卡跟併卡一起 | 二、三 |
| 12 | 併卡 | 一張卡好幾個動作：一次叫醒，每個動作各自一筆結果與證據 | 三（跟併卡一起） |
| 13 | 連續叫醒到上限時 | 由系統告訴人一聲（現在只記 log） | 二（提案） |
| 14 | 開關 | `llm.wake_after_card`：`true`（預設）｜`false`（只記一筆、不開輪） | 二（提案） |

## 契約

### 1. 第一段：已經有的介面（照實記下來；要改先改那個分支的 ADR 與測試）

```python
# src/synox/agent/wake.py
MAX_WAKES = 3
EVENT = "[系統事件]"
QUIET = "〔沒事〕"

@dataclass
class CardOutcome:
    shown: str                      # 卡上的指令
    executed: bool                  # 真的執行了（✅ 而且過了 authorize）
    ok: bool = False                # 執行成功（沒有失敗信封、沒有丟例外）
    result: str = ""                # 給 AI 的結果（規劃 11.6 那一份；沒執行＝""）
    reason: str = ""                # 沒執行的原因（取消、節點不見了、沒有權限…）
    tool: str = ""                  # 工具名（證據帳本用）
    effect: str = "read"
    receipts: list = field(default_factory=list)

def event_text(outcome) -> str      # 叫醒那一輪的 user 訊息
def note_text(outcome, token) -> str   # 記進記憶的那一筆
def is_quiet(text) -> bool
```

| 入口 | 做什麼 |
|---|---|
| `ApprovalDesk.request(…, waker=None)` | 卡記得是哪個 `AgentLoop` 發的。`AgentLoop` 自己出的卡帶 `waker=self`；經 AI 呼叫的工具回 `needs_confirm` 出的卡從 `CaptureApi.waker` 拿。沒有 `waker`（人自己打的指令）＝照舊 |
| 按 ✅ | 用 `CardRunApi` 執行：每一則照常送給使用者、順便記下結果。kind=cli／mcp 的工具在 `app.tasks` 上跑（要同步跑完才收得到結果，不能卡住收訊的執行緒） |
| `AgentLoop.after_card(api, chat_id, user, outcome)` | 先 `note_card()`（結果寫進記憶），再看連續叫醒的次數；沒超過就在 `app.tasks` 上開 `wake_turn()` |
| `AgentLoop.note_card(chat_id, outcome, user, thread)` | 記一筆「確認卡的結果」。結果本身存成記號，組訊息時才換成包好分隔符的字（工具的字永遠在分隔符裡） |
| `AgentLoop.wake_turn(api, chat_id, user, outcome)` | 拿這段對話的鎖；額度用完就不跑；user 訊息＝`event_text(outcome)`；證據帳本先放 `Evidence(tool, effect, ok, carded=False, …, receipts)` |

- 取消（❌）、節點不見了、按的時候權限不過：`executed=False`、`reason` 寫原因，一樣叫醒。
- 執行中工具又要求確認（又出一張卡）：等那一張按了再叫醒。
- 指令開了問答在等人（例如驗證碼）：只記一筆、不叫醒（結果之後直接給人；這時叫醒只會插話）。
- 人看到的東西不變：執行的輸出照舊由系統直接送；叫醒那一輪 AI 的回覆是另外一則，在它後面。

### 2. 後兩段：`CardOutcome` 怎麼長大（都是有預設值的新欄位，第一段的呼叫不用改）

```python
@dataclass
class CardOutcome:
    …                                # 第一段的欄位照舊
    card_id: int = 0                 # #編號（0037）；0＝沒有編號
    status: str = ""                 # ""＝照 executed／ok 推；或下表的值
    report: dict | None = None       # 批次方案：workmode.report() 的結果
    items: list["CardOutcome"] = field(default_factory=list)   # 併卡：每個動作一筆（外層是整張卡）
    via: str = ""                    # 在哪裡按的：telegram｜discord｜web（過期＝""）
```

| `status` | 意思 | `executed` | 哪一段 |
|---|---|---|---|
| `""`／`executed` | 執行成功 | `True`，`ok=True` | 一 |
| `failed` | 執行了但失敗（併卡：第 k 個失敗、後面沒做；`items` 一筆一筆寫清楚） | `True`，`ok=False` | 一、三 |
| `cancelled` | 人按了 ❌ | `False` | 一 |
| `denied` | 按 ✅ 時以人的身分 authorize 不過 | `False` | 一 |
| `stale` | 按 ✅ 時發現資料在他看卡之後變了（批次方案） | `False` | 二 |
| `expired` | 過期，沒有人按 | `False` | 二、三 |

`event_text()` 多出來的部分（樣板都是程式裡的常數；工具的字一律在分隔符裡）：

| 情況 | 字 |
|---|---|
| 有 `card_id` | 開頭變成「[系統事件] 確認卡 #12：…」 |
| `report` 有 | 多一段「[系統核對] {headline}」＋`diff_lines`。核對沒過時結尾換成「核對沒過：把差異告訴使用者，他可以按『↩ 整批退回』。不要自己一筆一筆修。」 |
| `stale` | 「…沒有執行：資料在使用者看卡之後變了。重新查詢、重新規劃。」 |
| `expired` | 「…過期了，沒有執行。告訴使用者這張卡過期了；他還要的話再提一次。」 |
| `items` 有 | 每個動作一行：`1. {shown}（成功）`／`（失敗）`／`（沒有執行）`，各自的結果各自一個記號 |

- 證據帳本：`items` 裡 `executed=True` 的**每一筆**各放一筆 `Evidence`。
- 過期的叫醒沒有人按：回覆走那張卡當初送出去的通道（卡上記著 `chat_id` 與網頁的對話）；來源標 `system`（ADR 0025 §2）。
- 批次方案的卡：`result` 是 `apply` 的那一份；`report` 由 `workhost` 在叫完 `verify` 之後填。驗證者（[0036](0036-triangle-review.md)）在這一輪 AI 準備好回覆之後、送出之前跑。

### 3. 防迴圈與不混輪（第一段已有；這裡寫清楚邊界）

- 每段對話（記憶鍵）一個計數：開一輪叫醒＝加 1；**人說了一句話＝歸零**；到 `MAX_WAKES` 之後只寫記憶、不開輪。計數只在記憶體。
- 叫醒的那一輪可以再提出危險動作（再出一張卡）；那張卡的結果又會叫醒——所以才要計數。
- 驗證者沒過叫醒執行者修一次（[0036](0036-triangle-review.md)）也算一次。
- `run_turn` 與 `wake_turn` 用同一把鎖：人話正在跑＝叫醒排在後面；反過來也一樣。人的訊息**永遠不會**被接在 `[系統事件]` 後面變成同一則。
- 第二段要補的三件小事（提案）：
  1. 到上限時由系統送一則給人：「（AI 已經連續接手 3 次，先停在這裡。要它繼續就跟它說一聲。）」同一次連續只說一次。
  2. 同一張卡只叫醒一次（有 `card_id` 之後記在一個小集合裡；重複的丟掉）。
  3. `llm.wake_after_card = false`：`after_card()` 只做 `note_card()`。這是行為上的大改動，出問題時要能一行關掉。

## 不做的事

- **不替 AI 重試**：執行失敗就是失敗，交給 AI 與人決定。
- **不在叫醒時放寬任何檢查**：不跳過核准卡、不跳過第 4 關、不帶解鎖。
- **人自己打指令出的卡不叫醒**：沒有 AI 在等。照舊記一句。
- **頻道 AI 不叫醒**（它本來就不出卡）。常駐助理（心跳）不受影響。
- **背景執行的指令**（`background: true`）的結果不交給 AI：AI 只拿到「開始了」。
- **不跨通道**：在哪裡按的，回覆就在哪裡。
- **重開之後不補叫**（卡都沒了）。
- **不把好幾張卡的結果合成一輪**：一張卡一輪，照順序排（併卡是「一張卡」）。

## 測試怎麼寫

第一段的測試在那個分支的 `tests/test_ai_wake.py`（這份不重複）。後兩段各自的 PR 要加的：

第二段（跟工作模式的 PR 一起；假工具、`FakeAdapter`、假時鐘、`app.tasks` 用同步的假實作）：

1. 批次方案按 ✅、核對過了：叫醒那一輪的 user 訊息有 `#編號`、有「[系統核對]」與 `report` 的 headline；`apply` 的結果在分隔符裡。
2. 核對沒過：有差異行；結尾是「不要自己一筆一筆修」；AI 那一輪想叫 `batch` 裡的工具改第 2 筆＝被 G1 擋（[0035](0035-workmode-core.md)）。
3. `stale`：`executed=False`、字裡有「資料…變了」；工作狀態回到 `query`。
4. 批次方案的卡過期：叫醒一次、字裡有「過期了，沒有執行」；回覆出現在當初那段對話；來源是 `system`。
5. 連續叫醒到上限：人收到「先停在這裡」一則，而且只有一則；人說一句之後又可以叫醒。
6. 同一張卡的結果交兩次：只開一輪。
7. `llm.wake_after_card = false`：記憶裡有那一筆、`FakeAdapter` 沒有多被叫一次。
8. 第一段的測試（`tests/test_ai_wake.py`）不改就過；`CardOutcome` 的新欄位都有預設值。

第三段（跟併卡的 PR 一起）：

9. 一張卡三個動作、第 2 個失敗：一次叫醒；三行分別是（成功）／（失敗）／（沒有執行）；證據帳本有兩筆（做了的那兩個）。
10. 一般的卡過期：叫醒一次。
11. AI 自己收回的卡（`card__void`）：不叫醒。
12. 宣告 `callers` 只收 `human` 的指令：叫醒那一輪照樣叫不到（那一輪的來源是 `ai`）。
13. `scripts/eval_assistant.py` 既有題目的分數不退。

## 跟規劃不一樣的地方

| 規劃 | 這份 | 為什麼 |
|---|---|---|
| 取消、過期各叫醒一次 | 多 `stale`、`denied`、`failed`（併卡）三種 | 卡有這三種結局（[0037](0037-approval-cards-upgrade.md)），AI 要分得出來 |
| 沒寫「沒有要接著做的」 | 第一段的實作加了 `〔沒事〕`（不送出、不記） | 不然每按一次卡，AI 都會多說一句沒有內容的話。這是那個分支的決定，這份照記 |
| 最多連續 3 次，之後沒寫 | 到上限時告訴人一聲（提案） | 不說的話，使用者只會看到「按了卡之後 AI 沒反應」 |
| 沒寫開關 | `llm.wake_after_card`（提案） | 要能一行退回舊行為 |
| 沒寫併卡與批次方案 | `CardOutcome` 加有預設值的欄位，不另做一種結果 | 第一段的介面已經在用；後兩段只能往上加 |
