# ADR 0026：在手機上打開工具的畫面——要用才開一條臨時通道，時間到自己關

- 日期：2026-11-14
- 狀態：**已採用**（2026-11-14；分支 `feat/secure-apps`（S1–S14 的程式；最後一包程式的合併是 `ccf6049`，S15 收尾另一筆合併））。真的通道、手機瀏覽器的實測（P1–P14）還要擁有者在別台電腦做。
- 基準：分支 `dev`，commit `6b4253c`。前提：[ADR 0025](0025-guard-core-and-stepup.md)（門禁核心與手機驗證器）與「工具服務 ADR」
  （分支 `feat/tool-apps` 的 `docs/adr/0024-tool-apps-services.md` 第三版；跟 `dev` 的 0023 撞號，見 0025 開頭）。
- 分工：[實作計畫](../lab/2026-11-14-stepup-remote-plan.md)。攻擊清單：[../security/web-threats.md](../security/web-threats.md)。
- 標籤：**已查證**／**推測**／**待實測**／**提案值**（同 0025）。
- 平台現實：維護者的開發機**不開埠、不碰防火牆、不開通道、不跑下載來的程式**。通道程式只會在擁有者自己選的電腦上、由擁有者核准之後執行；
  這裡的每一段邏輯都用直接呼叫與「假的通道」驗證。真的通道、真的手機，只有擁有者做（計畫的實測清單）。

> **先講清楚：這個功能會把一個工具的畫面放到公開的網際網路上（一段時間）。** 網址是隨機的、很難猜，但它是公開的：知道網址的任何人都敲得到門。
> 進不進得來，靠的是 SYNOX 自己的門（一次性連結＋手機驗證器），不是「沒人知道網址」。沒按就不開；時間到一定關；SYNOX 重開一律是關的。

## 擁有者的要求（協調者轉述；原話是中文語音，這裡拿到的是整理過的摘要）

- 「我希望服務可以在手機上打開：從 Telegram 開我本機的服務，然後打開一個網站在手機上操作、看一看，然後關掉。整個流程要簡單、由 SYNOX 做完，但安全變得非常重要。」
- 「我最擔心的是有人用漏洞繞進我的網路、攻擊我的電腦、偷我的資料——雲端服務通常就壞在這裡。駭客會試垃圾輸入、繞過權限和路徑。
  把這些抓出來，檢查每一個使用者輸入，盡量擋掉惡意攻擊，並確認輸入是使用者、代理、還是別人送的。盤點風險，再做一個乾淨好用的架構。」
- 擁有者的 LINE bot 已經有一版：Cloudflare 的臨時通道、要用才開、開幾小時自己關、管理頁還是要密碼。
- 擁有者 2026-11-04 那份「從 Telegram 預開服務」的研究的結論照用：把門直接交給 Telegram 帳號比本機登入弱，所以門前要多一樣不經過 Telegram 的東西；AI 不碰連結與驗證碼；備好的東西一定要有時限。

## 給使用者的說法（畫面上的字照這個寫；草稿）

| 名詞 | 一句話 |
|---|---|
| 手機入口 | 「平常工具的畫面只有這台電腦打得開。**開手機入口**＝SYNOX 借一條臨時的通道，給你一個只有這一次有用的網址，你在手機上打開、打驗證碼，就能用這個工具的畫面。」 |
| 會開多久 | 「預設 30 分鐘，10 分鐘沒動也會關。關了網址就作廢，下次是新的。」 |
| 誰進得來 | 「要同時有三樣：SYNOX 傳給你的連結、你手機驗證器上的數字、而且是第一個進來的。連結只能用一次。」 |
| 會看到什麼 | 「只有這一個工具的畫面。SYNOX 的主機台、其他工具、這台電腦的檔案，從這個網址都碰不到。」 |
| 要知道的事 | 「通道是 Cloudflare 提供的，資料會經過它的機器。很在意的資料請回到電腦前看。」 |

## 決定（每題一行；理由在後面各節）

| # | 題目 | 決定 |
|---|---|---|
| 1 | 通道 | **Cloudflare 的臨時通道（`cloudflared` 的 quick tunnel）**，跟 LINE bot 同一種：這台電腦只往外連，不開對內的埠、不動防火牆、不用帳號。包在一個小介面後面，之後要換別家只換一個檔（**擁有者決定第 1 題**） |
| 2 | 通道接到哪 | **不接工具服務的埠**。接到一個新的、只為這一次開的**遠端閘門**（也只綁本機位址）；閘門驗過身分才用函式呼叫把請求交給那個工具的站。主機台、其他工具、其他路徑，通道那一頭根本沒有路 |
| 3 | 前提 | 沒設定手機驗證器＝這個功能不存在。另外要：擁有者在主機台開過總開關、核准過通道程式、這個工具宣告了 `remote`、擁有者替這個工具打開過「可以從手機用」。四樣少一樣都不開 |
| 4 | 誰能開 | 只有擁有者本人，在 Telegram 私訊或主機台，**每次都要一組新的驗證碼**（不吃 15 分鐘的解鎖）。AI、排程、系統、遠端自己：永遠不行，也不送確認卡 |
| 5 | 怎麼進門 | 一次性連結（鑰匙放在網址 `#` 後面，不會送到任何伺服器的網址紀錄）＋在手機頁面上**再打一組驗證碼**（**擁有者決定第 2 題**）→ 一個只給這個瀏覽器的登入；整條連線只會有這一個登入 |
| 6 | 能做什麼 | 讀、寫入類的動作。**危險的動作與匯出在遠端一律不行**（**擁有者決定第 4 題**）；回到電腦或 Telegram 做 |
| 7 | 什麼時候關 | 到時間（預設 30 分鐘，最長 120）、10 分鐘沒用、5 分鐘內沒人進門、打錯 5 次、被亂敲太多次、通道斷了、`/app_close`、手機頁面上按「關閉」、驗證器被關掉、SYNOX 結束。一律整組收掉：登入作廢、通道程式結束、閘門關埠 |
| 8 | 面對網際網路 | 閘門前面一個嚴格的請求檢查（方法、路徑、標頭、大小、JSON），全部白名單；錯誤一律固定的幾句、不透露原因；每分鐘次數有上限；紀錄不記對方送來的任何字 |
| 9 | 通道程式 | SYNOX **不下載、不更新**它。擁有者自己裝；在主機台核准一次（顯示路徑、大小、SHA-256）；之後每次啟動前對雜湊，不一樣就不跑 |
| 10 | 多人與容器 | 第一版只有擁有者能用手機入口（伺服器版也是）；同時最多一條；容器版不開放（跟工具服務一致） |
| 11 | 跟工具服務 ADR 的關係 | 工具服務的站**一個字都不用為遠端改寫規則**：閘門把請求改成它認得的樣子再交給它。需要它配合的六件小事列在最後「對工具服務 ADR 的請求」 |

## 1. 通道選哪一種

| | A `cloudflared` 臨時通道（建議） | B Cloudflare 具名通道＋Access | C 私人網路（Tailscale 這一類） | D 自己開埠／路由器轉埠 |
|---|---|---|---|---|
| 這台電腦要做什麼 | 跑一支程式，只往外連 | 同 A，另外要 Cloudflare 帳號與自己的網域 | 裝一套網路軟體（會裝虛擬網卡與服務，安裝程式自己會動防火牆規則） | 開對內的埠、改防火牆 |
| 手機要做什麼 | 什麼都不用裝 | 什麼都不用裝 | 裝同一套 App 並登入 | 什麼都不用裝 |
| 網址誰連得到 | **全世界**（網址隨機） | 全世界，但 Cloudflare 先擋一層登入 | **只有你的裝置** | 全世界 |
| 中間的人看得到內容嗎 | **Cloudflare 看得到明文**（加密只到它那裡） | 同 A | 看不到（端到端加密） | 沒有中間人，但也沒有加密（除非自己弄憑證） |
| 簡不簡單 | 最簡單（LINE bot 已經在用） | 要設定一堆 | 要裝兩邊、要帳號 | 違反這台電腦的規矩 |
| 結論 | **採用** | 之後可以當第二種 | **安全性比 A 好**，但不符合「簡單」與「不動防火牆」；之後可以當第二種 | 不做 |

照實說 A 的代價：（1）工具的畫面在那 30 分鐘是公開網站，掃網址的機器人敲得到門——所以門要夠硬（§3、§5）；
（2）你的帳目內容與你在手機上打的驗證碼會以明文經過 Cloudflare 的機器（驗證碼用過即廢，帳目內容不是）；
（3）臨時通道是 Cloudflare 免費提供、沒有保證的服務，可能哪天改規則或連不上（**待實測**：現在不用帳號還能不能開）。
C 在（1）（2）兩點都比 A 好；如果擁有者願意在手機裝 App、而且那台電腦可以讓安裝程式動網路設定，C 是更安全的選擇。介面留著，第一版只做 A。

## 2. 架構：通道只碰得到閘門

```
手機瀏覽器 ──https──> Cloudflare ══(cloudflared 往外連的通道)══> 遠端閘門 ──函式呼叫──> 這個工具的站（AppSite）
                                                               127.0.0.2:8861            （工具服務 ADR 的那個物件，不經過它的埠）
                                              主機台 127.0.0.1:8830、其他工具的埠：通道那一頭沒有任何路到這裡
```

- **遠端閘門**（`RemoteGate`）是一個只有 `handle(method, target, headers, body)` 的物件，掛在工具服務 ADR 那個唯一會開埠的函式上（`web/apps/listen.py`），
  綁寫死的 `127.0.0.2`、一個固定的埠（預設 8861）。**所以「誰敢開埠」仍然只有一個地方。**
- `cloudflared` 被告知的目的地只有閘門那一個位址。它是另一支程序，拿不到保管箱、拿不到任何金鑰；SYNOX 給它的只有那個本機網址。
- 閘門對裡面是**函式呼叫**，不是再連一次網路：它把通過檢查的請求改寫成工具站認得的樣子（Host 換成本機的、來源換成本機的、只留白名單裡的標頭），
  呼叫 `app_site.handle(...)`，再把回應過濾一次送回去。工具站原本的規則（「帶代理標頭的一律拒」「Host 只能是本機那一個」）**原樣留著**——
  哪天有人把通道直接指到工具的埠，它會整個壞掉，而不是悄悄對外。
- 開手機入口＝工具服務照常開（工具服務 ADR 的那一套：狀態、閒置、稽核都沿用）＋多掛一個閘門＋一條通道。
  如果服務是為了手機才開的，手機入口關的時候服務一起關；本來就開著的，只收掉閘門與通道。

## 3. 流程與每一道門

```
1  Telegram 私訊：/app_remote money        （或 /app_open money remote；主機台工具頁的「📱 開手機入口」）
2  SYNOX：「🔐 貼上手機驗證器現在的 6 位數（120 秒內）」      ← 這則回覆不會送給 AI
3  你打 6 位數 → 對 → SYNOX 檢查前提 → 開服務、開閘門、啟動通道（約 10–30 秒，待實測）
4  SYNOX：「📱 記帳的手機入口開好了（30 分鐘後自動關）：https://<隨機>.trycloudflare.com/#k=<一次性鑰匙>
           連結只能用一次，5 分鐘內要進去。用完打 /app_close money。」
5  手機打開連結 → SYNOX 自己的進門頁：「再打一次驗證器上的數字」（要比第 3 步新的一組）
6  對 → 這個瀏覽器拿到登入 → 進到記帳的畫面。SYNOX 傳一則：「📱 有人進來了。不是你的話：/app_close money」
7  用。最後 5 分鐘 Telegram 與畫面上各提醒一次。
8  /app_close money、畫面上的「關閉」、或時間到 → 整組收掉 → 「📴 手機入口關了（原因）。資料都在。」
```

| 門 | 擋誰 | 細節 |
|---|---|---|
| ① 只收擁有者、只收私訊、只收人 | 其他人、群組、AI、排程 | 指令是 `interactive`＋`callers: human`＋`owner_only`＋`private_only`；開的函式自己再查一次來源 |
| ② 開之前一組新碼 | 拿到 Telegram 帳號的人 | 不吃解鎖視窗；錯了照 0025 的規則計次 |
| ③ 連結的鑰匙 | 掃到網址的陌生人 | 256 位元隨機、只存雜湊、5 分鐘、只能換一次登入；放在 `#` 後面，瀏覽器不會把它放進請求的網址（Cloudflare 的網址紀錄、Telegram 的連結預覽都拿不到） |
| ④ 進門再一組新碼 | **看得到你 Telegram 訊息的人搶先用連結** | 這是 ②③ 擋不到的那一種：連結走的是 Telegram。進門頁上的碼不經過 Telegram。因為一組碼只能用一次，這一組一定是下一個 30 秒的 |
| ⑤ 只給這個瀏覽器的登入 | 之後才拿到網址的人 | `__Host-` 開頭、`Secure`、`HttpOnly`、`SameSite=Strict` 的 cookie；整條連線**只發這一次**，沒有第二個登入可以拿；每個請求都對；瀏覽器的識別字串變了就作廢 |
| ⑥ 工具站自己的登入 | 閘門萬一有洞 | 進門成功後閘門替這個人要一張工具服務的交接票，畫面照工具服務原本的流程換成分頁裡的 token；之後每個資料請求兩樣都要 |
| ⑦ 動作的權限與欄位檢查 | 亂送的參數 | 跟 Telegram 打指令同一個葉節點、同一份欄位檢查（0025 §4）、同一個 `policy.decide`，來源標成 `remote` |
| ⑧ 時間 | 忘了關 | 決定 7 |

為什麼遠端這裡用 cookie，而工具服務在本機特地不用：本機不用，是因為本機位址的 cookie 不分埠、會被送到別的程式聽的埠去。
遠端每一次都是一個全新的 https 網域，只有這一個站，沒有那個問題；而 cookie 讓「還沒進門的人連工具的畫面檔都拿不到」（`<script>` 帶不了自訂標頭，帶得了 cookie）。
「綁這個瀏覽器」照實說：不是認得出你的手機，而是「登入只發一次、只在第一個進門的瀏覽器裡」。換瀏覽器、清掉 cookie＝要重開一次入口。

## 4. 從外面能碰到的東西（白名單，其他一律 404）

| 還沒進門 | 進門之後 |
|---|---|
| `GET /`：SYNOX 的進門頁（**不是工具的檔**） | `GET /`、工具畫面的靜態檔、`/_synox/kit.js`、`/_synox/kit.css` |
| `GET /_synox/enter.js`、`/_synox/enter.css` | `POST /api/enter`（工具服務的交接票換登入）、`GET /api/me` |
| `POST /_synox/enter`（鑰匙＋驗證碼） | `GET /api/read/<名字>`、`POST /api/do/<名字>`（只有寫入類）、`POST /api/alive`、`/api/leave`、`/api/close-service` |

- **碰不到**：主機台的任何東西、其他工具、匯出（`/api/export/*`）、「先留著」「一直開著」這類放寬的設定、工具資料夾裡畫面以外的檔（工具服務本來就只從記憶體的快照回應）。
- **危險的動作**（例如刪一筆）遠端回固定的一句：「這個動作要回到電腦或 Telegram 做。」第一版不做「遠端每次打碼就可以」（多一種流程、多一種畫面；等用過再說）。
- **匯出**在遠端不行：檔案會落在手機上，而且整個內容經過 Cloudflare。
- 沒進門的人看到的錯誤跟「沒有這個網站」一樣；登入不對、路徑不在白名單、方法不對，回的都是同一個 404，不告訴對方差在哪。

## 5. 面對網際網路的檢查（`guard/http.py`，閘門的第一步；一份、可以單獨測）

| 項目 | 規則（不合＝固定的 400／404／413／429，連線關掉） |
|---|---|
| 讀進來之前 | 整個請求的標頭 ≤ 16 KB、最多 60 個、單一個 ≤ 4 KB；內容 ≤ 64 KB；等資料最多 15 秒（慢慢送的佔線攻擊）；同時最多 16 條連線 |
| 方法 | 只收 GET、POST |
| 內容長度 | 有 `Transfer-Encoding` 一律拒；`Content-Length` 出現兩次、不是純數字、跟實際不合一律拒（請求走私） |
| 路徑 | 只收 `/` 開頭、≤ 2048 字、全是可見的 ASCII；解一次百分比編碼之後：不准有 `..` 的段、`//`、`\`、空位元組、控制字元、非 ASCII；原字串裡不准有 `%2f`、`%5c`、`%00`、`%25`（編碼過的斜線、反斜線、空位元組、雙重編碼）；正規化之後要跟自己一樣 |
| 查詢參數 | ≤ 1024 字、最多 20 個、同名的只准一個 |
| 標頭 | `Host` 必須等於這次通道的網域（一字不差）；`Host`、`Cookie`、`Content-Type`、`Origin`、`X-SYNOX-App` 出現兩次＝拒；名字有怪字元＝拒；帶 `Service-Worker`、`Upgrade`＝拒 |
| 來源 | POST 的 `Origin` 必須是 `https://<這次的網域>`；`Sec-Fetch-Site` 有帶的話只收 `same-origin`（進門頁的第一次導覽收 `none`） |
| 內容 | POST 只收 `application/json`；必須是 UTF-8 的 JSON 物件、最多 4 層、同一個鍵不准兩次；字串過 0025 §4 的 `text`（長度、空位元組、控制字元、騙人的排版字元） |
| 次數 | 還沒進門：每分鐘 60 個請求；進門之後：每分鐘 240 個；被拒的請求累計 300 個、或驗證碼錯 5 次 → **整條入口收掉**並通知擁有者「有人在亂敲門，我先把手機入口關了」（提案值） |
| 回應 | 一律加：`Strict-Transport-Security`、`X-Robots-Tag: noindex`、`Cache-Control: no-store`、`Referrer-Policy: no-referrer`、工具服務原本那一組（CSP、禁止被框、nosniff…）；**永遠沒有** `Access-Control-*`；錯誤頁沒有版本、沒有路徑、沒有例外的名字 |
| 交給工具站之前 | 標頭只留白名單（`content-type`、`content-length`、`accept`、`user-agent`、`x-synox-app`、`sec-fetch-*`、改寫過的 `host`／`origin`）；Cloudflare 與代理加的標頭在這裡用完就丟 |
| 紀錄 | `data/security_audit.jsonl`：時間、事件、**對到的路由名稱**（不是原始路徑）、方法、狀態、位元組數、原因代碼、來源位址（只收格式正確的 IP 字串）。對方送來的路徑、參數、標頭、內容**一個字都不記**（防有人把假的紀錄行塞進檔案） |

模糊測試清單（全部用「把位元組餵給處理器」與「直接呼叫 `handle`」，不開埠；每一條都要回固定的拒絕、不丟例外、不呼叫到工具的函式）：
隨機位元組；只有半個請求行；超長的路徑、標頭、內容；`/../`、`/..%2f`、`/%2e%2e/`、`/.%2e/`、`/%252e%252e/`、`/..;/`、`//etc/passwd`、`/\..\`、`/C:/`、`/app/../../config.json`；
`%00`、真的空位元組、`\r\n` 夾在標頭值裡；全形的點與斜線（`．．／`）、組合字元、右到左控制字元、落單的代理字元；
`Content-Length` 兩個／負數／比實際大／比實際小；`Transfer-Encoding: chunked` 加 `Content-Length`；`Host` 兩個、`Host` 是別的網域、是 IP、帶埠；
絕對網址當路徑（`GET http://別人/`）；`OPTIONS`、`PUT`、`DELETE`、`TRACE`、`CONNECT`；JSON 是陣列、重複鍵、100 層巢狀、1 MB 的字串、不是 UTF-8；
沒 cookie、過期的 cookie、兩個同名 cookie、別條入口的 cookie；鑰匙用第二次、過期的鑰匙、對的鑰匙配錯的碼六次。

## 6. 來源與「這個輸入是誰送的」

- 經閘門進來的每個動作，來源標成 `remote`（0025 §2），帶著「哪一條入口」。工具站的稽核因此分得出「人在電腦前做的」與「從手機做的」。
- 收緊成「只收人」的指令，遠端做不到（`remote` 是另一類）。遠端能做的＝這個工具畫面宣告的寫入動作，沒有別的。
- AI 與排程碰不到閘門、碰不到開關：開、延長都只收人＋新碼；**關**誰都可以（AI、排程、系統都能關——關永遠是安全的方向）。
- 手機頁面上輸入的每個值，走的是跟 Telegram 打字同一份欄位檢查；差別只有前面多了 §5 那一層。

## 7. 通道程式（下載來的執行檔）怎麼管

| 項目 | 決定 |
|---|---|
| 怎麼來 | **擁有者自己裝**（LINE bot 那台是 `winget install --id Cloudflare.cloudflared`；或從官方發佈頁下載）。SYNOX 不替你下載、不替你更新，也沒有「自動安裝」的按鈕 |
| 在哪裡找 | `config.json` 的 `web.remote.tunnel.path`；沒寫就找系統路徑上的 `cloudflared`。找不到＝功能不可用，說一句怎麼裝 |
| 核准 | 主機台「🔐 安全」分頁（要先解鎖）：顯示完整路徑、大小、SHA-256、檔案的簽署者（Windows 讀得到的話，**待實測**），以及一句「請跟官方發佈頁上的雜湊對一下」。按「我核對過了，核准」才記進 `data/remote.json` |
| 每次啟動前 | 重新算雜湊；跟核准時不一樣（例如被更新了、被換掉了）＝不跑，請擁有者重新核准 |
| 怎麼跑 | 不經 shell、固定的參數（`tunnel --no-autoupdate --url http://127.0.0.2:<閘門埠>`）、空的工作資料夾、最小的環境變數、不給標準輸入；從它的輸出裡用嚴格的樣式抓出網址（只收 `https://<小寫英數與連字號>.trycloudflare.com`） |
| 怎麼停 | 先請它結束，5 秒沒結束就強制結束；SYNOX 自己結束時一定帶走它（Windows 用工作物件，`sandbox.py` 已經有類似的做法） |
| 斷了 | 不自動重開（重開會換網址，等於一條新的入口）：整條收掉、通知擁有者 |
| 這台開發機 | **永遠不跑它**。測試用 `FakeTunnel`（回一個假的網址、可以模擬起不來與中途斷掉）；測試檔自帶「誰敢開子程序、誰敢綁埠就失敗」的保險 |

照實說：通道程式是別人寫的程式，在你的電腦上用你的帳號跑；SYNOX 管得到的是「是不是你核准的那一個檔」與「只告訴它閘門的位址」，管不到它自己還做了什麼。
它預設會在本機另外開一個給自己看狀態用的埠（只有本機連得到；**待實測**能不能關）。使用者資料夾裡如果有 `cloudflared` 的設定檔，臨時通道可能開不起來（**推測**，照它的文件；doctor 檢查並提醒）。

## 8. 多人、容器、其他通道

- 伺服器版：第一版只有擁有者能開、能進（用擁有者自己的驗證器）。成員要從外面用，仍是營運者自己架反向代理的那條路（`docs/security.md`「網頁介面」）。
- 容器：不開放（工具服務在容器裡本來就不開）。之後要做，通道程式放在**另一個**容器，不放進 SYNOX 的映像檔。
- 同時最多一條手機入口（提案值）。多一條就多一個公開的網址，沒有好理由。
- 其他通道（具名通道＋Access、私人網路）：`Tunnel` 介面留著，這一輪不做。

## 9. 威脅清單（寫給擁有者看的）

| 誰 | 他怎麼做 | 我們怎麼擋 | 還剩什麼風險 |
|---|---|---|---|
| 掃網址的機器人 | 亂試各種網址、送垃圾 | 沒進門只看得到進門頁；其餘全是同一個 404；次數上限；敲太多次整條收掉 | 進門頁本身被看到（上面沒有任何你的資料） |
| 拿到你 Telegram 帳號的人 | 自己開手機入口 | 開之前要驗證器的碼 | 他同時拿到你的手機驗證器（同一支沒鎖的手機） |
| 看得到你 Telegram 訊息的人 | 你開了之後，他搶先點連結 | 進門還要一組不經過 Telegram 的碼；打錯 5 次整條收掉 | 同上 |
| 之後才拿到網址的人（瀏覽紀錄、截圖） | 再點一次 | 鑰匙只能用一次；登入只發一次；時間到網址作廢 | 沒有 |
| 借用你已經登入的手機的人 | 直接用開著的分頁 | 10 分鐘沒用就關、30 分鐘一定關；危險的動作與匯出遠端做不到 | 他在那幾分鐘內看得到、改得了這個工具的資料 |
| 想繞進你電腦的人 | 特製的路徑（`../`）、偷渡的請求、超大的內容、怪字元 | §5 的檢查；工具的檔只從記憶體回應，請求碰不到硬碟；通道那一頭只有閘門 | 閘門或 Python 標準函式庫裡還沒被發現的洞。所以它只開幾十分鐘、而且後面還有工具站自己的登入 |
| 想從這個工具跳到主機台或別的工具的人 | 改 Host、改來源、猜別的埠 | 通道只知道閘門；閘門只認這一個工具；主機台的登入是另一套，這裡沒有它的 cookie | 沒有路 |
| 假冒你的網站 | 送請求讓你的手機瀏覽器替他做事 | cookie 是 Strict、POST 要對來源、資料請求還要分頁裡的 token | 沒有已知的做法 |
| AI（被騙的） | 被一段文字說服「幫我開手機入口」「把驗證碼給我」 | 開關不在 AI 的工具裡、不送確認卡；沒有任何工具收驗證碼 | AI 用話術請你自己去開、自己把碼打在錯的地方（0025「擋不住的」） |
| 排程 | 半夜自己開 | 排不進去（`interactive`＋只收人） | 沒有 |
| Cloudflare（或它的員工、它被入侵） | 看經過的內容、改內容 | 擋不了：加密只到它那裡 | **真的存在**。所以危險動作與匯出不走遠端、時間短；很在意就回電腦前（或之後換成私人網路） |
| 被換掉的通道程式 | 把你裝的 `cloudflared` 換成別的 | 每次啟動前對雜湊，不一樣不跑 | 你核准的那一刻它就已經是假的（所以核准頁叫你對官方的雜湊） |
| 惡意的工具畫面（你裝的工具本身是壞的） | 在你的手機瀏覽器裡把資料帶走 | 內容安全政策擋連外；安裝報告明講 | 跟本機一樣擋不住「整頁導去外站」（工具服務 ADR「擋不住的」）；遠端多一個風險是它拿到的是手機的瀏覽器 |
| 這台電腦上的其他程式 | 直接連閘門的本機埠 | 一樣要鑰匙、碼、cookie | 它本來就能做更多別的事（這台電腦被佔領不在這份的防線內） |
| 你自己忘了關 | — | 時間到一定關；SYNOX 重開一律關；主機台與 `/apps` 一直顯示開著 | 沒有 |

## 10. 測試（配合開發機的限制）

- 閘門、請求檢查、入口的狀態機、次數限制、時間，全部是不碰網路的物件：`RemoteGate.handle(...)`、`RemoteManager(tunnel=FakeTunnel, listen=假的, clock=假的)`。
- 「讀進來之前」的那幾條（大小、逾時、走私）測的是處理器本身：把位元組放進記憶體裡的假連線餵給它，不開任何埠。
- 測試用的假手機 `RemoteClient`（記 cookie、帶對的 Host 與來源、會走完進門）給 SYNOX 與工具庫的測試用。
- 新的測試檔一律用 `no_sockets`（工具服務計畫定的保險），再加一條「誰敢 `subprocess.Popen` 就失敗」。
- 真的通道、真的手機：只在擁有者選的電腦上做，清單在計畫最後。在那之前，這份 ADR 裡標「待實測」的都不能當成已經成立。

## 擋不住的（照實寫進 security.md）

- Cloudflare 看得到經過的明文（§1）。
- 那幾十分鐘裡，網際網路上的任何人都敲得到閘門；我們靠的是門夠硬與時間夠短，不是沒人找得到。
- 同一支手機同時有 Telegram 與驗證器、而且沒上鎖被拿走：三道門都在對方手上。
- 通道程式本身是我們看不到內容的程式（§7）。
- 閘門用的是 Python 標準函式庫的 HTTP 伺服器，它不是為了直接面對網際網路設計的；前面有 Cloudflare 擋掉一部分畸形的請求，後面有 §5，但這仍然是「短時間、單一使用者」才合理的做法，不能拿來長期對外。

## 不做（這一輪）

成員的手機入口；一直開著的入口、開機自動開；延長超過 120 分鐘；遠端的危險動作與匯出；遠端看主機台；同時多條入口；SYNOX 自動下載或更新通道程式；
具名通道、Access、私人網路；容器版；自己的網域與憑證；把通道交給 AI 或排程。

## 這份 ADR 沒有驗證的事

- **所有關於 `cloudflared` 的行為**：不用帳號的臨時通道現在還開不開得起來、要幾秒、它把原本的 `Host` 傳過來還是改掉、它加哪些標頭、它自己開的狀態埠、有設定檔時的行為、在 Windows 上結束得乾不乾淨。
- **所有手機瀏覽器的行為**：`__Host-` cookie 在這種網域上收不收、網址 `#` 後面的鑰匙在 Telegram 內建瀏覽器裡還在不在、Telegram 的連結預覽會不會先去敲一次門（設計上敲了也沒關係：鑰匙不在請求裡）。
- 工具服務 ADR 第三版自己還沒實測的那些（`127.0.0.2` 綁不綁得起來等）是這份的前提。
- 標「提案值」的數字。
