# 常駐的小吉祥物（側欄或標題列）預設開還是關

狀態：待處理（要維護者決定；沒決定＝**預設關**；這題不擋 [吉祥物接線那張交辦單](../20261119-153430-mascot-states-wiring.md)，那張單不做常駐吉祥物）

## 問題一句話

之後要做的方向 ②——側欄或標題列放一隻小型、會跟著狀態變（平常／想事情／完成／要你確認）的常駐吉祥物，使用者可以在設定裡關掉——新安裝時預設要開還是關？

## 脈絡

- 外觀包的四個吉祥物狀態（`mascot.idle／think／happy／warn`）現在只在少數地方出現，開場之後畫面幾乎只剩文字，所以換外觀的價值主要在顏色（[交辦單 §2.1](../20261119-153430-mascot-states-wiring.md)）。
- 已排好的順序：① 把狀態接到 AI 實際發生的事、③ 空狀態與錯誤頁以吉祥物為主角（那張交辦單做）；② 常駐吉祥物之後再做，要先定預設值。
- 常駐的東西一直在畫面上：會分散注意力、手機畫面空間小、對動態敏感的人比較不舒服（就算有「減少動態效果」也一樣佔位置）。
- 做了 ① 之後，使用者在「等 AI」「核准卡」「完成」這些時刻本來就會看到吉祥物；常駐那一隻是加碼，不是唯一的出現機會。
- 不論預設是什麼，都會有：設定裡的開關（每個人自己的，跟外觀模式同一類設定）、深淺色、減少動態效果時靜止。

## 選項

| 選項 | 一句話 | 建議 |
|---|---|---|
| A | 預設關：設定 → 外觀多一個「在側欄顯示小吉祥物」開關，想要的人自己打開 | ✅ 建議（預設做這個） |
| B | 預設開：新安裝就顯示，不想要的人自己關 | |
| C | 有套外觀包時預設開、沒套（SYNOX 預設外觀）時預設關 | |
| D | 不做常駐吉祥物，只做 ① ③ ④ | |

建議 A 的理由：① 做完後吉祥物已經會在對的時刻出現；常駐的東西佔空間、對手機與對動態敏感的人比較不友善；先關、讓想要的人打開，比先開再讓人去找開關的打擾小。

## 驗收

- 選 A／B／C：設定頁有開關、預設值照選的；重新整理、重開 SYNOX 後保留；手機寬度不擋到輸入框；深淺色、減少動態效果都有測試；沒有外觀包時用 SYNOX 預設的吉祥物，不出現空框。
- 選 D：在吉祥物接線那張交辦單的 §2.4 把 ② 標成「不做（維護者決定）」。

## 不要做的事

- 沒決定之前，不要在任何分支上做常駐吉祥物。
- 不要為了它新增必填的 slot 或改顏色契約（[ADR 0042](../../adr/0042-theme-tokens-single-source-and-forward-compat.md)）。
- 不要預設播放會一直動的動畫（不論開或關，常駐那一隻平常都應該是靜止的）。
