# S3：沒有隔離的電腦上，標「官方不保證安全」的工具要不要預設不執行

狀態：待處理（要擁有者決定；建議做，但要等真隔離的後端存在）

## 問題一句話

Windows 的真隔離（MXC 或 AppContainer）做出來之後，帶 `vendor_no_security_guarantee` 的工具在「保護等級＝沒有」的電腦上，要不要預設不執行、由擁有者逐個放行？

## 脈絡

- 現在（S1、S2、S4 之後）：個人版照常執行，只在警告下面多一行「這台實況」；伺服器版沒有真隔離時只給擁有者（S2）。見 [ADR 0041 §5](../../adr/0041-pack-warnings.md)。
- [ADR 0022](../../adr/0022-ecosystem-bridge-and-sandbox.md) 決定 17：沒有隔離的電腦上，第三方 T2 預設不執行。S3 是把這個 code 也算進去。
- Windows 個人版目前**沒有任何**真隔離後端（`auto`＝none；jobobject 只限資源；appcontainer 只有介面；MXC 只有探測結果）。
  現在就做「預設不執行」＝這類工具在 Windows 個人版上全部不能用，而且沒有任何設定能讓它們「安全地」用。
- 擁有者確認（第一次啟用逐條勾「我知道」）已經存在；S3 會再多一道「這台沒有隔離，要不要還是放行」。
- `kind=python` 的工具任何後端都包不到：S3 做了之後，它們在每一台電腦上都是「保護等級＝沒有」。
- 真機驗證（[交接書](../sandbox-real-machine.md)）還沒做；S1 的字是否讓人看得懂，會影響 S3 要不要做。

## 選項

| 選項 | 一句話 | 建議 |
|---|---|---|
| A | 等 Windows 的 MXC 或 AppContainer 後端做好、真機驗過之後再做：沒有隔離的電腦上預設不執行，設定頁逐個「放行」，放行寫進 `packs.lock` | ✅ 建議（預設做這個） |
| B | 現在就做：沒有隔離＝預設不執行（Windows 個人版上這類工具全部要手動放行） | |
| C | 不做：維持現在（確認＋實況那一行），永遠不擋執行 | |
| D | 只對 `kind=cli`／`mcp stdio` 做，`kind=python` 另外處理（例如一律只能擁有者手動叫、AI 不能自己叫） | 可以跟 A 一起決定 |

## 驗收

- 選 A：隔離後端合併並通過真機清單之後，另開分支實作；有一張新的真機清單項目「沒有隔離的電腦上預設不執行、放行之後才執行、放行寫進鎖、取消放行」。
- 選 B：同 A 的驗收，外加「Windows 個人版上現有的帶警告工具升級後的提示」不讓人以為工具壞了。
- 選 C：在 ADR 0041 §5.4 把 S3 標成「不做」並寫原因。

## 不要做的事

- 不要在沒有任何真隔離後端的時候就把「放行」做成預設勾好（那等於沒做）。
- 不要把 S1 的「這台實況」改成「已在 sandbox」來代替 S3。
- 不要因為 S3 就拒絕安裝（擁有者先前定了「一律可以安裝」，S4 也是只加紅字）。
