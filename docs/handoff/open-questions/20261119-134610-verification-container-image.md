# 驗證機能不能拉官方 Python 容器映像來做沙盒真機驗證

狀態：待處理（要擁有者決定；沒決定＝不拉，相關項目寫略過）

## 問題一句話

做沙盒真機驗證（[交辦單](../20261119-134608-sandbox-real-machine.md)）時，驗證機可不可以從 Docker Hub 拉官方的 `docker.io/library/python:3.12-slim`、照 digest 用它跑我們自己寫的探針？

## 脈絡

- 清單 4.4（C-1～C-5）、4.5（D-1）、S2-c、L-5 要驗「選了容器之後真的在容器裡跑、看不到主機的檔案、沒宣告網路就斷網」；沒有映像就驗不了。
- SYNOX 安裝的第 1 關只收 `docker.io`／`ghcr.io`／`quay.io` 上帶 `@sha256:` digest 的映像；本機 build 的 `localhost/…` 會被拒，所以不能自己 build 一個代替。
- 拉下來的映像是「下載來的東西」：規則是只拉官方的、照 digest，而且容器裡只跑自己寫、掛進去的 `tool.py`；映像本身的 Python 會被執行（那就是容器的用途）。
- 驗證機是專門做驗證的電腦（不是開發機），但仍然要照「不開對外的埠、不 `--privileged`、不掛 `docker.sock`」做。
- 映像大約 50 MB 上下（slim 版），拉一次、驗完刪掉。

## 選項

| 選項 | 一句話 | 建議 |
|---|---|---|
| A | 同意：只拉 `docker.io/library/python:3.12-slim` 一個，記下 digest、照 digest 用，驗完刪掉 | ✅ 建議（預設做這個——但沒有擁有者明確同意前，接手者照 D 做） |
| B | 同意，但只在 Linux 實驗室機器（不在 Windows 的 Docker Desktop 上） | |
| C | 同意，但改用擁有者指定的另一個官方映像（例如 `python:3.13-slim`），digest 由擁有者給 | |
| D | 不同意：C-1～C-5、D-1、S2-c、L-5 全部寫「略過：未同意拉映像」，這幾項的驗收留到之後 | 沒決定時的預設 |

## 驗收

- 選 A／B／C：清單第六節的備註寫「擁有者同意拉 `<映像>`」；回報裡有 `docker.io/library/python@sha256:<64 字>`；收尾時刪掉（這台本來沒有的話）。
- 選 D：那幾項都是「略過：未同意拉映像」，備註寫擁有者接受略過。

## 不要做的事

- 不要拉任何別的映像（第三方 pack 的映像、`latest` tag、沒有 digest 的寫法）。
- 不要為了能用 `localhost/…` 而放寬 SYNOX 第 1 關的映像規則。
- 不要在擁有者平常用的開發機上拉或執行任何映像。
