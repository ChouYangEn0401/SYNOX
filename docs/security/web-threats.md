# 網頁最常被打的地方，SYNOX 各自怎麼擋

- 這是一份**會一直更新**的清單：每做完一包、每發現一個洞，就回來改這裡的「狀態」。下一個接手安全的 session 先讀這份。
- 最後更新：2026-11-14（分支 `feat/remote-access`；基準 `dev` 的 `6b4253c`）。這一版是**設計階段**寫的：標「已做」的是今天 `dev` 上就有的；
  標「計畫」的還沒寫程式，括號裡是[實作計畫](../lab/2026-11-14-stepup-remote-plan.md)的第幾包。
- 相關：[ADR 0025](../adr/0025-guard-core-and-stepup.md)（門禁核心、手機驗證器）、[ADR 0026](../adr/0026-remote-tool-apps.md)（手機入口）、工具服務 ADR（分支 `feat/tool-apps`）、[../security.md](../security.md)（給使用者看的整體說明）。
- 狀態：**已做**＝有程式、有測試｜**計畫**＝設計好了、排進哪一包｜**缺口**＝知道、還沒有對策｜**不適用**＝SYNOX 沒有那種東西。
- 怎麼更新：做完一包，把那一列改成「已做」並在「在哪」補上測試的位置（`tests/檔名::測試名`）。S15 會加一個測試，檢查這份文件裡寫的測試都真的存在。

## 三個面，風險不一樣

| 面 | 誰連得到 | 今天有沒有 |
|---|---|---|
| 主機台（`127.0.0.1:8830`） | 只有這台電腦 | 有 |
| 工具服務（`127.0.0.2:<埠>`） | 只有這台電腦 | 計畫（工具服務 ADR） |
| 手機入口（臨時的公開網址 → 遠端閘門） | **網際網路上的任何人都敲得到門**，開著的那幾十分鐘 | 計畫（ADR 0026） |

## 這一輪之後還開著的（照嚴重程度）

1. **6b／26**：主機台的登入只靠 cookie，本機的其他帳號與程式有辦法拿到。手機驗證器把後果從「什麼都能做」縮到「看得到、做不了敏感的事」，但看得到本身就是問題。要另開一張問題單。
2. **27、17**：程序內的 Python 工具沒有隔離；套件與工具沒有簽章。
3. **22**：通道業者看得到明文。
4. **18**：第三方寫的名稱與簡介進系統提示。
5. **11**：主機台的一般 API 沒有對 `Host`。
