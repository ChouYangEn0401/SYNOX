# 保管箱打不開時，手機驗證器要不要「擋住一切危險動作」？

- **狀態**：待處理
- **擁有者原話**：「原則上我們的 skills……儘可能做好不要做出這種意外的漏洞。」

## 問題一句話
驗證器的紀錄壞掉時已經改成「擋住」；但整個保管箱打不開時，照原設計仍當成「沒設定驗證器」，這段期間危險動作不用驗證碼。

## 脈絡
- 安全審查第 5 點修了「紀錄讀不出來」；「整個保管箱打不開」是計畫裡寫明的另一條路，沒有一起改。
- 保管箱打不開時，大部分工具本來就不能用（資料都在裡面）。
- 另一個小問題：保管箱壞了時，`python -m synox stepup reset` 可能也會失敗。

## 選項
| 選項 | 一句話 | |
|---|---|---|
| A | 保管箱打不開時，危險動作一律擋，訊息講清楚怎麼修 | **建議** |
| B | 維持現在（當作沒設定） | |

## 驗收
- 選 A：`guard/stepup.py` 的保管箱路徑改成拒絕，補測試，`stepup reset` 在保管箱壞掉時給清楚的說明。

## 不要做的事
- 不要為了「讓它能用」而在保管箱外另存驗證器密鑰。
