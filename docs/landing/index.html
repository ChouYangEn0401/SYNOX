它是什麼

一個 bot、三個入口、工具自己挑

SYNOX 是一支在你電腦上跑的程式。它開著的時候，你從 Telegram、Discord 私訊，或這台電腦的網頁跟它講話，三邊看到的是同一個助理、同一份資料。 出廠時它是空的：要記帳就裝記帳，要接 Notion 就裝 Notion，不要的不裝。

聊天就是介面打 /help 看指令，或直接打字交給 AI。網頁版多一個「工具」頁，每個指令一張卡、照宣告產生表單，填好按執行。
接你自己的 AI預設用這台電腦登入的 Claude Code；也可以填 OpenAI、Anthropic、Gemini 的金鑰，或相容端點（公司的網址、自己電腦上的 Ollama）。也可以先不用 AI，指令照樣能用。
提醒與排程是本體/remind_add 08:00 吃藥 每天提醒；/schedule_add 21:00 /money_month 每天固定替你跑一個指令。這兩個不用裝工具。
常駐助理在背景巡網頁「主控」頁：一個沒有工具的常駐助理，每隔一段時間（預設 45 分鐘）看一輪任務和提醒，有事才通知你；你的偏好寫在 soul.md，它每次醒來先讀。
個人版或伺服器版自己用就選個人版。要給家人、社團用，選伺服器版：每個人一份加密資料、各自的 AI 額度、角色（訪客／成員／管理員）。
工具庫（SYNOX_Libs）官方工具另外放在工具庫：記帳、隨手記，以及接 Notion、Todoist、Google 日曆、Apple 提醒事項的工具。一個工具一個 .synoxpack，看完報告才裝。

本機優先

資料在你的硬碟上，會出門的只有兩條路

沒有雲端帳號、沒有 SYNOX 的伺服器。它的網頁只聽 127.0.0.1（程式裡寫死，設定改不了），其他裝置連不到。

筆記、記帳、提醒是密文每個 .json.enc 用 Fernet（AES-128-CBC＋HMAC）加密，檔案金鑰由主金鑰衍生；主金鑰在 Windows 上用 DPAPI 包住，只有這台電腦的這個 Windows 帳號解得開。
AI 金鑰、工具的 token 進保管箱安裝精靈和網頁「連接」表單把金鑰存進保管箱（密文）；網頁永遠只回「有填」和最後 4 碼。Telegram 刻意不收密碼，因為聊天會留紀錄。
出門的第一條：聊天平台你跟 bot 之間的訊息經過 Telegram／Discord 的伺服器，bot 訊息不是端對端加密。這是平台的事實，SYNOX 修不了。
出門的第二條：你選的 AI有設定 AI 時，送出去的是你那一句話、系統提示、最近 6 輪對話，和工具回的那幾行。AI 看不到你的整個資料庫，只看得到它叫的指令回了什麼。

伺服器版要講清楚：架這台的人（營運者）技術上看得到所有人的資料。完整的表、每個檔案的保護方式、沒有做的保護，都寫在 repo 的 docs/security.md。

怎麼開始

三步裝好，不用打指令

  1. 拿到 SYNOX，雙擊 Setup.bat 安裝程式 SYNOX-Setup-<版本>.exe（不要系統管理員，Python 和套件都附在裡面，不用上網）最後一步會自動跑這個； 用 git clone 或 Download ZIP 拿到的就自己雙擊。第一次會花幾分鐘，出現一個顯示進度的視窗，不用打任何字。
  2. 照安裝視窗點四頁
    • 這台給誰用？只有我（個人版）或一群人（伺服器版）。
    • Telegram bot 的 token：照畫面跟 @BotFather 拿一個貼上。沒有 Telegram 也可以先跳過，只用網頁，或之後在設定頁接 Discord。
    • 你是誰：畫面給你六個數字，傳給你的 bot，它就認得你了。之後也能在網頁「設定 → 聊天通道」配對 Telegram 或 Discord 帳號。
    • AI 從哪裡來：Claude Code、API 金鑰、相容端點，或先不用。按「測一下」確認接得通。
  3. 裝幾個工具 剛裝好的 SYNOX 是空的，/help 會提醒你。發佈版旁邊的 tools\ 就是工具庫： 
    synox tools list                      看有哪些、哪些已裝
synox tools install notes money       看完報告才裝，不會自動全裝
    或點兩下 .synoxpack，或在網頁「設定 → 裝功能」上傳。三條路都跑同一套安全檢查。
Telegram 教學（圖文） Discord 教學（圖文） Discord 的名詞：bot、伺服器、頻道、intent

教學連結指向 repo 裡的 docs/tutorials/telegram/、docs/tutorials/discord/、docs/discord-concepts.md；從 repo 的 docs/landing/index.html 打開這一頁才點得到。 之後要開 bot：雙擊桌面的「SYNOX」捷徑或 Start.bat；關掉那個小視窗或雙擊 Stop.bat 就停。

安全

AI 能做什麼，只有一個地方決定

每個指令都宣告自己是唯讀、會寫入，還是危險。AI 要用任何工具，都過同一個判斷：這個人、這個工具、從哪裡來。危險的一律先出卡。

確認卡刪除、花錢、動到外面的服務：AI 停下來，卡送給你，按 ✅ 才執行，❌ 就作廢。卡有期限，別人按不了你的卡。
裝工具要過五關宣告檢查 → 靜態掃描（報告給你看）→ 雜湊鎖（之後檔案被改過就不載入）→ 每次呼叫前驗參數 → AI 的判斷＋確認卡。
信任層級 T0／T1／T2T0 只有宣告（遠端 MCP）、T1 掃得到的原始碼、T2 附執行檔或外部程式。T2 要你一字不差輸入發行者名字才裝得了。它是「讓你知道在信任誰」，不是沙盒。
保管箱金鑰與 token 密文存放；打不開就報錯，絕不當成空的再蓋過去。工具的 secret 只放進子程序環境，不進命令列參數，不進 log。
伺服器版的邊界每個人一把金鑰，A 解不開 B 的檔；成員看不到第三方的 python 工具；沒有真隔離的子程序工具只給擁有者。
沙盒與容器Linux 的 bwrap／systemd 後端，和 podman／Docker 容器後端都寫好了，但只驗證過組出來的指令，還沒在真機跑過。Windows 個人版預設沒有沙盒。
唯讀、會寫入：直接做 危險：先問你 信任層級與還沒驗證的

「這套系統現在能保證什麼、不能保證什麼」與「沒有做的保護」兩節都在 docs/security.md，三種使用情境分開寫。

工具與 pack

一個工具＝一個資料夾，壓起來就是 .synoxpack

資料夾裡放 pack.json（宣告：叫什麼、怎麼執行、每個指令危不危險、要什麼權限）、SKILL.md（給 AI 看）、README.md（給人看）和你的程式。 裝進去之後，每個指令同時是一個 Telegram 指令、一個 AI 工具、網頁工具頁的一張卡。

kind: cli命令列子程序

大部分工具選這個。任何語言，每次呼叫開一次程序，JSON 進、JSON 出。用 Python 的話，SDK 十行就接上。

kind: mcp · stdioMCP 伺服器（長駐）

你已經有 MCP 伺服器，或工具啟動很慢。每個使用者一個長駐程序，第一次呼叫才開、閒置 10 分鐘收。

kind: mcp · http遠端 MCP

對方已經架好 https 的 MCP 伺服器。這台不跑任何程式，只寫 pack.json；token 或 OAuth 存保管箱。

十行入門

from typing import Literal
from synox_sdk import tool, serve

@tool("READ")
def greet(name: str, style: Literal["casual", "formal"] = "casual"):
    """跟某人打招呼。"""
    return f"{name}，您好。" if style == "formal" else f"嗨 {name}！"

if __name__ == "__main__":
    serve()
synox-sdk init --from tool.py --name hello --title "👋 打招呼"
synox-sdk run greet Amy style=formal
synox-sdk zip .        →  dist/hello-0.1.0.synoxpack

工具庫怎麼運作

官方工具在另一個 repo SYNOX_Libs：一堆 .synoxpack 加一份目錄 index.json（名稱、版本、說明、建議組合、sha256）。 發佈版把打包好的工具庫放在 SYNOX 資料夾的 tools\，SYNOX 不用設定就找得到；放別處就寫 config.json 的 packs.library。

synox tools install 先對雜湊，再走跟上傳檔一樣的五關。每個工具標穩定度： 🔧 test 🧪 alpha 🚧 beta ⭐ stable， /help、工具頁、安裝報告、doctor 都看得到。目前工具庫的工具全部是 alpha。

工具也宣告它照哪一版 SDK 寫（requires.sdk）；跟這台不合的會明說、不裝。

文件給誰裡面有什麼
docs/ecosystem.md使用者、作者怎麼找、裝、更新、移除工具；第三方怎麼做一個 pack 給人裝；之後的路線（哪些是提案）
docs/tools.md作者從這裡開始：三條接入路怎麼選、權限欄位、secret、確認來回、測試、安全自檢表
docs/sdk.md作者Python SDK：@tool、serve()、secret()、synox-sdk 指令
docs/pack-format.md作者、維護者pack.json 每個欄位的完整規則、升級與環境建置
examples/作者可以照抄的範例：SDK、不用 SDK 的任何語言、Node 的 MCP stdio、遠端 MCP

現在的狀態

這是 alpha，先說清楚哪些還沒驗過

  • 請先別拿來放重要資料。格式、設定、資料檔都還可能改。
  • 工具庫的工具全部標 🧪 alpha。接外面服務的（Notion、Todoist、Google 日曆、Apple 提醒事項）和 Discord 通道都只用假傳輸測過，還沒對真實服務驗證。
  • Windows 安裝程式的腳本做好了，還沒真的打包、還沒在空白電腦上試。Setup.bat 的完整路徑也沒在陌生電腦跑過。
  • 沙盒與容器後端還沒在 Linux 實機驗證。Windows 個人版預設沒有沙盒：子程序工具跟 SYNOX 一樣看得到整台電腦。
  • 伺服器版的營運者看得到使用者的資料。給別人用之前要講清楚。
  • AI 的對話記憶只在記憶體。重開 bot 就忘，每段留最近 6 輪。
  • 只有 Windows 的安裝器。程式本身跨平台，但 macOS／Linux 要自己建環境。
  • 專案網址還沒公開。現在是從給你 SYNOX 的人那裡拿到檔案；synox about 也會老實印「還沒公開」。

拿到檔案之後

安裝程式

雙擊 SYNOX-Setup-<版本>.exe，照畫面按。不要系統管理員，裝在 %LOCALAPPDATA%\Programs\SYNOX， Python、套件、工具庫都附在裡面，不用上網。最後一步自動跑 Setup.bat，接著就是上面的四頁。

git clone 或 ZIP

git clone <專案網址> SYNOX
cd SYNOX
Setup.bat            雙擊也可以

工具庫另外下載 tools 資料夾放進 SYNOX 資料夾。工程師模式：python -m synox init 在終端機一問一答，或照 config.example.json 自己寫。

README：完整說明與常見問題 全部文件的索引 版本紀錄

移除：Uninstall.bat。你的資料在 data\（筆記、記帳、金鑰 .synox.key），不要刪；金鑰不見，加密的資料就再也打不開。 加密的資料只有這台電腦、這個 Windows 帳號解得開，換電腦前先別刪舊的。
