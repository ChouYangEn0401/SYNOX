SYNOX 全貌

一個裝在自己電腦上的小助手核心：聊天通道（Telegram、Discord、網頁）接上 AI，再用可安裝的「工具」擴充能力。核心本身不帶任何工具，要什麼自己裝。

SYNOX 0.2.0SDK 0.2.09 個工具・0.1.1・alpha測試版本，尚未在空白電腦驗證

三個角色

核心（SYNOX）

通道、對話助理、權限、排程、保管箱、網頁介面、安裝檢查。出廠沒有任何工具。

SDK

工具與核心之間的合約。工具在 pack.json 宣告 requires.sdk，版本不合就不裝、不載入。

工具庫（SYNOX_Libs）

所有工具的統一管理處。打包成 .synoxpack，附 index.json（版本、雜湊、穩定度、建議群組）。

怎麼運作

flowchart LR
  U[使用者] --> C[通道 Telegram / Discord / 網頁]
  C --> A[對話助理 + 權限檢查]
  A -->|呼叫| T[已安裝的工具 packs/]
  A --> L[AI 來源 Claude Code / API 金鑰]
  R[Runtime 迴圈] --> H[Heartbeat 每 45 分鐘]
  H --> M[常駐助理 + soul.md]
  M -->|有事才通知| C
  T -->|回報狀態| R
  LIB[(SYNOX_Libs .synoxpack)] -->|安裝檢查後| T

一則訊息的路

通道收到訊息 → 核心認出是誰、是什麼角色 → 對話助理決定要不要呼叫工具 → 每個工具指令先過權限檢查，危險指令要使用者按確認卡 → 結果包在隨機分隔符裡交回 AI，標明是資料不是指令。

安裝與工具

安裝分兩段，彼此獨立：先裝空殼 SYNOX，再自己挑工具。

步驟git clone 路線安裝程式路線（設計完成，未打包）
取得clone 或下載 zipSYNOX-Setup.exe（Inno Setup＋可攜版 Python）
裝核心雙擊 Setup.bat：找 Python、建 .venv、裝套件（有 wheelhouse 就離線）每個使用者自己裝，不需管理員
引導synox init（視窗精靈，沒有 tkinter 就退到文字版）裝完自動跑引導
裝工具synox tools list、synox tools install <名字>，或網頁「設定 → 裝功能」上傳 .synoxpack。先對 sha256，再走安裝檢查，使用者核准才裝，不提供「全部裝」。
 
synox init               # 引導：模式、通道、AI 來源、工具庫位置、挑工具
synox tools list         # 工具庫有哪些、裝了哪些
synox tools install notes todo
synox open               # 打開網頁介面
synox doctor             # 健康檢查（含 heartbeat 與工具狀態）

工具裝在 SYNOX 資料夾的 packs/<名字>/，鎖定資訊在 data/packs.lock，兩者都不進 git。

已知風險：程式與資料目前在同一個資料夾，用 zip 覆蓋升級時會不會洗掉已裝工具與資料，還沒驗證。計畫把資料與工具移到獨立資料夾（見「接下來」A）。

常駐與心跳

Runtime 迴圈

常駐排程：每個任務有逾時、退避重試、狀態與日誌。工具可用 SDK 回報狀態，也讀得到其他工具的狀態。

Heartbeat

預設每 45 分鐘（15～1440 可調、可關）喚起常駐助理巡一次。沒有新狀況就不叫 AI；有安靜時段與每日上限。

常駐助理與 soul.md

常駐助理沒有工具，只決定要不要通知、要不要追加偏好。soul.md 記使用者偏好，加密存放，也以唯讀方式進入對話助理的 system prompt（僅擁有者）。

Claude 的 prompt cache 預設只留 5 分鐘，要留 1 小時得在請求上另外標記。SYNOX 目前沒有標，所以 45 分鐘的 heartbeat 還吃不到快取，列為 MVP 之後的工作。

網頁介面

  • 對話：左側歷史，全幅聊天。
  • 工具：頁內左側是「群組」，群組內用 tab 分工具；每個工具有說明、指令、參數表單與執行。使用者可自行新增、改名、搬移群組，排法每人一份、加密存放。
  • 主控（僅擁有者）：heartbeat 開關與間隔、常駐助理狀態、任務清單與日誌、清空記憶、soul.md 編輯。
  • 設定：AI 來源、聊天通道、功能（工具）、帳號、備份。
  • 打開時有約 1.7 秒的開場動畫，尊重「減少動態效果」；深淺色跟隨系統；離線可用，沒有外部資源。

網頁只綁本機位址。伺服器版若設了 web.public_url，成員與訪客也能登入，只看得到自己的對話與工具；是否收緊為只給管理員，待決定。

安全

  • 安裝前：宣告檢查與靜態掃描；使用者看過報告並核准才裝；每個工具記錄信任層級。
  • 執行時：可選沙盒或容器；每個指令過角色權限；危險指令需確認卡；確認憑證綁工具、指令、參數與使用者，用一次就失效。
  • 資料：金鑰存加密保管箱；soul.md、網頁排法加密；工具只能寫自己的資料夾。
  • 不寫死任何一台電腦的路徑；測試會擋下追蹤檔案中的本機路徑與未標記的兄弟資料夾猜測。

接下來

A. 資料與工具獨立存放

使用者資料、已裝工具、config 移到獨立資料夾，升級程式不碰。

B. 線上工具清單

讀網址型 index.json，下載後驗證雜湊並安裝；網頁也做出清單與一鍵安裝。

C. 網頁型工具（web-app）

工具可宣告自己帶一個本機網頁前端；工具頁加「打開」按鈕，由 SYNOX 代理並帶登入驗證，內嵌顯示。需新增能力宣告與審查。

D. 把既有小工具接上 SDK

PersonalToolZoo 的工具直接在原專案加 SDK 與 pack.json，不搬進工具庫；ClawBot 的天氣、地圖等也可抽成工具。
